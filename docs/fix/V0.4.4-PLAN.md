## 0. 摘要

| # | 问题 | 判定 | 根因 | 修复归属 |
| --- | --- | --- | --- | --- |
| 1 | `mod_group_id` 中间段应为作者名（如 `com.besson.tutorial`） | 真问题 | `lib/scaffold.js` 的 `inferParams` 默认包名固定 `com.example.<modid>`，作者（`authors`）只用于 `mod_authors`，不参与包名 | 0.4.4：包名改为 `com.<authorSlug>.<modid>`；作者未填时回退 `com.example.<modid>`（过渡） |
| 2 | `src/main/java` 目录仍是 `com/example/...`，应与 `mod_group_id` 一致 | 真问题（与 1 同源） | 迁移目标目录由 `params.package` 决定；包名错则目录错 | 0.4.4：包名正确后目录自然一致，并加「目录 ↔ 包名 ↔ `mod_group_id`」三重校验 |
| 3 | 先写文档，不改代码 | 本文件 | — | 等待确认后实施 |

**用户确认的边界**：

- 包名中间段填**作者名**；
- 下一个版本（0.4.4）起**作者名强制填写**；
- 未填作者时（过渡期）允许回退 `com.example.<modid>`，但 0.4.4 起表单与 API 都要求作者。

## 1. 现状与根因

### 1.1 包名来源

`lib/scaffold.js` 的 `inferParams`：

```js
const packageName = String(input.package ?? meta?.group ?? '').trim() || `com.example.${modid}`
```

- 新建项目弹窗没有「包名」输入，`package` 永远是空 → 默认 `com.example.<modid>`；
- `authors` 只进入 `mod_authors`（ASCII 化后的 `gradleAuthors`），**不参与包名**；
- MDK 模式与内置模板都走 `inferParams`，所以两者都得到 `com.example.<modid>`。

### 1.2 Java 目录

MDK 迁移（`migrateExamplePackage`）把官方示例包迁移到 `params.packagePath`：

```js
const newDir = join(javaRoot, params.packagePath)
```

`packagePath` 由 `params.package` 转换而来。因此：

- 包名是 `com.example.mymod2` → 目录是 `src/main/java/com/example/mymod2`；
- 用户看到「Java 目录不该是 example」与问题 1 是**同一个根因**。

### 1.3 作者现状

- `meta.authors` 已能写入（0.4.3），弹窗有「作者」输入；
- 但作者可以为空，且不参与包名；
- 下一步把作者提升为必填。

## 2. 修改方向（0.4.4）

### 2.1 包名规则

新增 `authorSlug(author)`（`lib/scaffold.js`）：

- 取可见 ASCII（与 `asciiName` 一致）；
- 转小写；
- 去除非 `[a-z0-9_]` 的字符；
- 空则返回 `''`。

包名生成：

```text
作者已填：com.<authorSlug>.<modid>        // 例：com.besson.tutorial
作者未填：com.example.<modid>            // 0.4.4 过渡回退；0.4.4 起表单/API 要求作者
```

- 若作者含中文（`authorSlug` 为空）：0.4.4 起**报错**并提示「作者名请使用英文」；
- 若用户显式传 `package`（API），优先使用用户值（高级用法），但校验合法性；
- 包名段必须合法：`[a-z][a-z0-9_]*`（每段），总长度合理。

### 2.2 Java 目录一致性

- 包名正确后，`packagePath` 自动变为 `com/besson/tutorial`，迁移与新建都会落到对应目录；
- 增加校验（在 `validateMdkOutput` / 内置模板校验中）：
  1. `gradle.properties` 的 `mod_group_id` === `params.package`（已有）；
  2. `src/main/java/<packagePath>` 存在，主类在其中；
  3. 所有 `.java` 的 `package` 与所在目录一致（至少主类与迁移后的示例包）；
  4. 旧示例包目录已删除、无 `example` 残留（已有残留扫描）。

### 2.3 作者必填（0.4.4 起）

- **表单**：`CreateProjectModal` 的「作者」改为 `required`，空时禁用「创建」并提示；
- **API**：`project.create` 与 `scaffold.apply {source:'mdk'}` 在作者为空时报错（返回明确文案）；
- **meta**：`createProject` 写 `authors`（已有），必填校验在 API 层；
- **兼容**：已存在的项目不受影响；旧调用方（agent）需要补 `authors`；
- **内置模板**：`mod_authors` 与包名同样使用作者段。

### 2.4 内置模板与 MDK 共用

- `inferParams` 是两条生成路径的公共入口，改一处即可；
- 内置模板的 `gradle.properties.tpl` 已有 `mod_group_id={{package}}`，无需改模板；
- MDK 的 `applyMdkParams` 已写 `mod_group_id: params.package`，无需改逻辑，只需包名正确。

### 2.5 校验清单（生成后）

| 项 | 期望 |
| --- | --- |
| `mod_group_id` | `com.<authorSlug>.<modid>`（或显式 `package`） |
| Java 目录 | `src/main/java/com/<authorSlug>/<modid>/`，主类存在 |
| `package` 行 | 与目录一致 |
| 旧示例包 | 已删除，无 `examplemod` / `ExampleMod` 残留 |
| `mod_authors` | 等于作者（ASCII） |
| `mods.toml` | `modId` / `authors` 正确（或 `${...}` 由 Gradle 展开） |

## 3. 测试

- `test/26`：
  - 作者 `Besson` → `params.package === 'com.besson.<modid>'`、`gradle.properties mod_group_id` 正确；
  - 作者为空（0.4.4 过渡）→ `com.example.<modid>`；作者必填后 → 报错；
  - 作者含中文 → 报错（提示英文）。
- `test/30`（MDK）：
  - 真实/夹具 MDK apply 后目录为 `com/besson/<modid>`；
  - `mod_group_id`、Java 目录、`package` 行三者一致；
  - 旧包删除、残留为空。
- `test/12`：弹窗「作者」必填（渲染断言）。
- 真实 MDK：下载 47.4.16 → apply → `gradlew compileJava`（人工/后台）。

## 4. 兼容与迁移

- **只影响新建**：已生成的项目不会被自动改包；
- 已填作者、包名仍是 `com.example.*` 的旧项目：如需修正，重新执行 `scaffold.apply`（会覆盖）或手工改包；
- 0.4.4 起作者必填属于**行为变更**（PATCH 内的收紧），文档与 CHANGELOG 注明；
- 版本：`0.4.4` PATCH（新增作者必填与包名规则，不破坏数据格式）。

## 5. 待确认的决策

1. **作者名转写**：只保留 ASCII 小写字母/数字/下划线（建议），中文作者名直接报错，还是尝试拼音转写？
2. **作者必填范围**：0.4.4 起 `project.create` 与 `scaffold.apply` 都强制，还是仅 UI 强制、API 允许空（回退 `com.example`）？
3. **包名是否允许用户手填**：新增「包名（可选）」输入框，默认按作者段生成（建议允许，高级用户可自定义）？
4. **未填作者的回退**：0.4.4 过渡期是否保留 `com.example.<modid>`（建议保留一个版本），还是直接报错？
5. **旧项目**：是否需要提供「重新生成包名」的工具（建议暂不提供，避免误改用户代码）？
