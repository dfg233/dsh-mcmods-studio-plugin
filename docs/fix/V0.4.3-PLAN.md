## 0.1 教程要点（本次抓取）

教程（Forge 1.20.1）在「模组基本配置」与「gradle.properties」两节给出的操作，正是 v0.4.3 要自动化的内容：

1. **包结构**：官方示例包 `com.example.examplemod` 改成自己的包（教程示例 `com.besson.tutorial`）；**必须用 IDE 的重命名功能**（IDEA `Shift+F6`），「不然会报错」——说明要连同类名引用、资源引用一起改。
2. **主类名**：`ExampleMod` 改成自己的类名（教程示例 `TutorialMod`），同样用重命名。
3. **MODID**：只能使用小写字母、下划线（数字亦可），**不能有短横线**，否则加载模组时崩溃。
4. **`mod_group_id`**：必须与主类所在包一致——「如果这个 `mod_group_id` 不正确，模组加载器就找不到你的模组主类」。
5. **`gradle.properties`**：
   - `mod_authors=Besson`（作者字段，出现在模组列表）；
   - `mod_description` 的多行要写成 `\n` 转义，不能直接回车；
   - `mapping_channel=parchment`、`mapping_version=2023.09.03-1.20.1`。
6. **Parchment 安装**（教程「更改映射」一节，与 Parchment 官方文档一致）：
   - `settings.gradle` 的 `pluginManagement.repositories` 加 `maven { url = 'https://maven.parchmentmc.org' }`；
   - `build.gradle` 的 `plugins` 在 ForgeGradle 插件之后加 `id 'org.parchmentmc.librarian.forgegradle' version '1.+'`；
   - 改 `mapping_channel` / `mapping_version`。
7. **运行验证**：`gradlew runClient`（Tasks → forgegradle runs）或 `gradlew build`。

## 1. 问题 1：示例包未整体迁移

### 现象

用官方 MDK 生成后：

- `src/main/java/com/example/examplemod/Config.java` 仍在 `com.example.examplemod` 包；
- `ExampleMod` 类名只改了主类，其他类里的 `ExampleMod.MODID`、`ExampleMod.LOGGER` 等引用未改；
- 新旧包混存、引用断裂，`gradlew build` 失败。

### 根因

`lib/mdk.js` 的 `replaceMainClass`：

1. `findMainClass` 只找**第一个**含 `@Mod(` / `implements ModInitializer` 的类；
2. 只替换该类的 `package` 行与类名，并把它移动到新包路径；
3. 同目录下的其他 Java 文件、资源目录（`assets/examplemod`、`data/examplemod`）完全没动。

官方 MDK 1.20.1 的示例源码（以官方 zip 为准）通常包括：

```text
src/main/java/com/example/examplemod/
├── ExampleMod.java          # @Mod 主类
├── Config.java              # 配置（引用 ExampleMod.LOGGER / MODID）
├── client/ClientSetup.java
├── event/ClientEvents.java
└── event/ModEvents.java
src/main/resources/
├── META-INF/mods.toml
├── pack.mcmeta
└── assets/examplemod/...    # 示例资源（如有）
```

### 修改方向（0.4.3）

新增 `migrateExamplePackage(projectPath, params)`，在 `applyMdkParams` 中**替代**单个主类的处理：

1. **识别示例包**：
   - 旧包默认 `com.example.examplemod`（官方 MDK 默认 `mod_group_id`）；
   - 也兼容从 `gradle.properties` 的 `mod_group_id` 读取；
   - 只迁移「旧包目录」下的文件（`src/main/java/com/example/examplemod/`），不碰其他包，避免误改用户代码。
2. **整体迁移 Java 文件**（等价于教程的 IDE 重命名）：
   - 遍历旧包目录下所有 `.java`；
   - 替换 `package <旧包>` → `package <新包>`；
   - 替换旧主类名（如 `ExampleMod`）→ `params.ClassName`（全文替换，含 `ExampleMod.MODID` 等引用）；
   - 替换字符串字面量 `"examplemod"` → `"<modid>"`（`MODID` 常量值、资源 ID）；
   - 写入 `<packagePath>/<相对路径>`，删除旧目录。
3. **资源目录迁移**：
   - `src/main/resources/assets/examplemod/` → `assets/<modid>/`；
   - `src/main/resources/data/examplemod/` → `data/<modid>/`；
   - 目录内 JSON 的 `"examplemod"` 引用替换（如 model/texture 路径）。
4. **mods.toml**：
   - 若使用 `${mod_id}` 占位（官方 MDK 默认），由 Gradle 展开，保持不动；
   - 若是字面量 `examplemod`，替换为 `<modid>`。
5. **残留扫描与校验**：
   - 扫描 `src/main/java` 与 `src/main/resources`，查找 `examplemod` / `ExampleMod` 残留（排除 `mods.toml` 的 `${...}`）；
   - 有残留时**报错**（见待确认），避免生成不可编译工程；
   - 校验所有 `.java` 的 `package` 与目录一致；
   - 校验 `gradle.properties` 的 `mod_group_id` 等于新包（教程强调的硬性约束）；
   - 校验主类存在于新包、旧包目录已删除。

### 验证

- 用 fixture 模拟官方 MDK（含 `ExampleMod.java`、`Config.java`、`client/ClientSetup.java`、`event/*`）→ 生成后无 `examplemod` / `ExampleMod` 残留、包目录一致；
- 用真实官方 MDK zip（用户提供或联网）跑 `gradlew build`。

## 2. 问题 2：作者字段

### 现状

- `lib/mdk.js` 的 `applyMdkParams` 已写 `mod_authors: params.gradleAuthors`；
- `inferParams` 支持 `authors`（`input.authors ?? meta?.authors`）；
- 但：新建弹窗没有「作者」输入；`project.create` 不接收 `authors`；`lib/meta.js` 的 `createProject` 不写 `authors` 字段。

### 修改方向

1. **新建弹窗**：增加「作者」输入框（默认空；可预填 `process.env.USERNAME`？见待确认）；
2. **`project.create`**：接收 `authors`，传给 `createProject`（`meta.authors`），并在 `scaffold` / MDK 分支传给生成逻辑；
3. **`createProject`（`lib/meta.js`）**：meta 增加 `authors: String(input.authors ?? '').trim()`；
4. **两套生成**：
   - 内置模板：`gradle.properties` 的 `mod_authors`（已有）、`mods.toml` 的 `authors`（由 `${mod_authors}` 展开）；
   - MDK：`applyMdkParams` 的 `mod_authors`，以及 `mods.toml` 字面量 `authors`（若存在）；
   - 继续遵守 ASCII 规则（`gradleAuthors = asciiName(authors)`）。
5. **校验**：填了作者时 `gradle.properties` 的 `mod_authors` 非空。

## 3. 问题 3：mapping 与 Parchment

### 现状

官方 Forge MDK 默认：

```properties
mapping_channel=official
mapping_version=1.20.1
```

`build.gradle` 只有 `net.minecraftforge.gradle` 插件；`settings.gradle` 的 `pluginManagement.repositories` 只有 Forge / Gradle 插件门户。MDK 模式没有改这些。

### Parchment 安装步骤（教程与官方文档一致）

1. `settings.gradle` 的 `pluginManagement.repositories` 增加：

```groovy
maven { url = 'https://maven.parchmentmc.org' }
```

2. `build.gradle` 的 `plugins` 块，**在 ForgeGradle 插件之后**增加：

```groovy
id 'org.parchmentmc.librarian.forgegradle' version '1.+'
```

3. `gradle.properties` 的 mapping 改为 parchment：

```properties
mapping_channel=parchment
mapping_version=2023.09.03-1.20.1
```

（1.20.1 对应 Parchment 版本 `2023.09.03-1.20.1`，与插件内置模板一致；版本规则见官方文档：`YYYY.MM.DD-MC版本`。）

4. 前置条件：ForgeGradle ≥ 5.1.20、Gradle ≥ 7.1.1（官方 MDK 1.20.1 满足）。

### 修改方向（0.4.3）

1. **版本矩阵**：`lib/version-matrix.js` 增加 `parchmentVersion`（1.20.1 → `2023.09.03-1.20.1`），供两个生成路径共用；
2. **`applyMdkParams`**：
   - `gradle.properties`：`mapping_channel=parchment`、`mapping_version=<parchmentVersion>`（若 MDK 有这些 key，则替换；没有则追加）；
   - `build.gradle`：若 `plugins` 块存在且无 librarian，插入 `id 'org.parchmentmc.librarian.forgegradle' version '1.+'`（放在 forgegradle 行之后）；
   - `settings.gradle`：`pluginManagement.repositories` 内插入 `maven { url = 'https://maven.parchmentmc.org' }`（若不存在）；
3. **校验**：`build.gradle` 含 `librarian.forgegradle`、`settings.gradle` 含 `parchmentmc`、`gradle.properties` 的 `mapping_channel=parchment`；失败提示；
4. **回退**：提供 `mapping: 'official' | 'parchment'`（默认 parchment）；`official` 时跳过上述修改；
5. **范围**：先做 Forge；NeoForge 1.20.1 的 Parchment 配置与 Forge 不同（NeoGradle），Fabric 用 `loom.layered()`（官方文档），列为后续或按官方 MDK 实际结构调整（见待确认）。
