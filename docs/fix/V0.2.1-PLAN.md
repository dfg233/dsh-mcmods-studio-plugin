## 0. 摘要

v0.2.1 只处理内容编辑的两个明确问题，不进入 M2：

1. Pattern / 材料键输入框无法正常换行；
2. 「回滚上次内容」只依赖页面内状态，切换页面后消失，且只能回滚最近一次。

第 2 项用**持久化内容历史**替代，不再使用单个 `lastContentBackup`。

## 1. 现状与根因

### 1.1 输入框无法换行

当前 Pattern 与材料键都是受控 `Textarea`，每次输入都立即把文本切成数组，再 `filter(Boolean)` / `filter(line.length > 0)` 后 `join('\n')` 回填。

结果：

- 在末尾按 Enter 产生一个空行；
- 空行立即被过滤掉；
- 受控值又被写回为没有末尾换行的字符串；
- 光标无法进入下一行，表现为「按 Enter 没反应」。

Pattern 还要求保留前导/尾随空格（空格代表空槽），因此不能在输入阶段做 `trim`。

**修复方向**：

- 输入阶段保留原始文本（包括空行、末尾换行、Pattern 空格）；
- 只在「保存/预览」时解析为数组；
- Pattern 保留每行原样，只去掉完全空的行；材料键忽略空行；
- 切换配方类型时不丢失已输入文本。

### 1.2 回滚状态丢失

当前 `ItemsTab` 只有：

```text
lastContentBackup（React state）
```

问题：

- 切页、刷新、重新打开项目后状态消失；
- 只能记住最近一次备份；
- 新的写入会覆盖旧备份提示；
- 用户无法看到「改过哪几步、每一步改了什么」。

## 2. 目标

- 输入框可正常换行、可输入多行 Pattern 与材料键；
- 内容历史持久化到项目，切页/重开项目仍可见；
- 可选择任一历史步骤回滚；
- 回滚该步时，递归回滚该步及其后的所有步骤；
- 被回滚的记录不立即删除；
- 用户在下一次修改后，旧回滚记录才归档或删除；
- 不改变物品设计数据与已有资源文件的格式。

## 3. 非目标

- 不做物品属性/代码的通用 undo；
- 不做跨项目历史；
- 不自动清理全部备份；
- 不实现任意文件编辑历史；
- 不改变 `content.apply` 的资源格式与路径规则。

## 4. `BUG-01`：换行修复

### 4.1 交互

- Pattern 输入框允许按 Enter 增加行；
- 材料键输入框允许按 Enter 增加条目；
- 空行在输入时可见，保存时忽略；
- Pattern 的每行空格保留；
- 粘贴多行文本不丢行。

### 4.2 数据流

```text
输入框原始文本 patternText / keysText
  → 保存/预览时解析
  → pattern: 去空行、保留空格
  → keys: 去空行、trim 后按 key=item 解析
  → 写入 content.preview / content.apply
```

不再在 `onChange` 中把数组立即回填到输入框。

### 4.3 验收

1. Pattern 输入三行，按 Enter 能到下一行；
2. 保存后生成三行 `pattern`；
3. 材料键输入两行，按 Enter 能到下一行；
4. 保存后生成两个材料键；
5. 末尾空行不进入 JSON；
6. Pattern 的 ` R `、` S ` 空格保留；
7. 不出现「输入后光标跳回上一行」。

## 5. `FEAT-02`：内容历史

### 5.1 语义

历史按项目记录，每个内容写入是一步：

```text
H1 → H2 → H3 → … → Hn
```

每一步保存**该步写入前的资源状态**。

选择回滚 `Hk` 时：

1. 从 `Hn` 到 `Hk` 逆序恢复每一步的备份；
2. 结果等于 `Hk` 写入之前的状态；
3. `Hk` 及其后的步骤标记为 `rolledBack`；
4. `Hk` 之前的步骤保持 `active`；
5. 不删除任何备份。

> UI 文案必须写「回滚到这一步之前」，避免用户误以为保留该步结果。

### 5.2 为什么逆序恢复

每一步只备份自己改到的文件。若正序恢复，后面的步骤可能再次覆盖前面的文件；逆序恢复能保证：

- 后面的步骤先撤销；
- 前面的文件最后回到目标状态；
- 只在后续步骤创建的文件，会由后续步骤的备份删除。

### 5.3 存储

新增项目文件：

```text
<项目>/.mcstudio/content-history.json
```

结构：

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "id": "h_1790000000000_ab12",
      "sequence": 1,
      "at": "2026-10-31T00:00:00.000Z",
      "itemId": "ruby_sword",
      "title": "红宝石剑：语言/配方/模型",
      "files": [
        { "kind": "lang", "path": "src/main/resources/assets/mymod/lang/zh_cn.json" },
        { "kind": "recipe", "path": "src/main/resources/data/mymod/recipes/ruby_sword.json" }
      ],
      "backupDir": "<备份目录绝对路径>",
      "status": "active"
    }
  ]
}
```

字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 历史步 id，稳定唯一 |
| `sequence` | 递增序号，用于排序与回滚范围 |
| `at` | 写入时间 |
| `itemId` | 关联物品 |
| `title` | 人类可读摘要 |
| `files` | 该步涉及的文件 |
| `backupDir` | 该步写入前备份目录 |
| `status` | `active` / `rolledBack` / `archived` / `failed` |

备份仍在插件数据目录：

```text
$DSH_HOME/mcmods-studio/backups/<project>/
```

历史文件只存元数据，不复制资源内容。

### 5.4 写入流程

```text
1. 计算变更
2. 创建备份
3. 写入资源文件
4. 成功：追加 history entry（active）
5. 失败：用备份恢复资源，追加 failed 或不追加
```

约束：

- 若资源写入成功但 history 写入失败，必须尝试用备份恢复资源，并报告；
- `content.apply` 返回值增加 `historyEntry`；
- 旧调用方忽略新字段仍可工作。

### 5.5 回滚流程

```text
1. 读取 content-history.json
2. 找目标 entry；只允许 active
3. 取目标及之后所有 active entry
4. 逆序 restoreContent(entry.backupDir)
5. 逐个标记 rolledBack
6. 返回恢复的文件数与被回滚步数
```

失败处理：

- 中途失败立即停止；
- 已完成的步骤保留 `rolledBack`；
- 返回明确失败原因，不假装成功；
- 不自动删除备份，允许人工恢复。

### 5.6 归档规则

- 回滚后：`rolledBack`，历史可见，备份保留；
- 用户在回滚后**下一次成功执行 `content.apply`** 时：
  - 先把旧 `rolledBack` 标记为 `archived`；
  - 再创建新的 `active`；
  - `archived` 默认不在主列表展示，可切换「显示已归档」查看；
- 不在回滚完成的瞬间删除；
- v0.2.1 不自动物理删除备份；清理留到后续设置页/维护命令。

### 5.7 UI

「物品」页顶部改为常驻按钮：

```text
历史记录
```

打开弹窗/抽屉：

- 列出当前项目内容历史，默认过滤当前物品；
- 显示时间、物品、文件数、状态；
- `active` 行有「回滚到这一步之前」；
- `rolledBack` 行标记「已回滚」，不可再次回滚；
- `archived` 行默认隐藏；
- 回滚确认文案包含「将回滚该步及其后 N 步」；
- 回滚后刷新物品/资源，不需要刷新页面。

移除「上次内容写入已备份」的单次提示；它由历史列表取代。

### 5.8 API

新增：

```text
content.history.list { path, itemId?, includeArchived? }
content.history.rollback { path, entryId }
```

保留：

```text
content.rollback { path, backupDir }
```

`content.rollback` 标记为兼容接口，v0.2.x 内保留；新 UI 不再调用它。

`content.apply` 返回：

```json
{
  "files": [],
  "backupDir": "...",
  "historyEntry": { "id": "h_...", "sequence": 3 }
}
```

### 5.9 边界

- 历史文件损坏：返回空列表并告警，不阻塞内容编辑；
- 备份目录缺失：该步标记 `failed`，不可回滚；
- 项目移动：`backupDir` 可能失效，回滚时报「备份不存在」；
- 同一项目并发写入：`content.apply` 需要写锁或最后写入者检测；
- 历史过长：v0.2.1 只限制 UI 展示条数，不自动删除；
- 回滚后用户不修改：历史保持 `rolledBack`，不归档。

## 7. 验收步骤

### 7.1 换行

1. 打开物品编辑器 → 配方类型选「有序合成」；
2. Pattern 输入三行，按 Enter 能换行；
3. 材料键输入两行，按 Enter 能换行；
4. 保存，检查 JSON 的 `pattern` 为 3 行、`key` 为 2 项；
5. 确认 Pattern 空格未丢；
6. 末尾空行未写入。

### 7.2 历史持久化

1. 对同一物品连续做 3 次内容修改（例如先改中文名，再加配方，再加标签）；
2. 切到「项目」页再回到「物品」页；
3. 打开「历史记录」，仍能看到 3 步；
4. 刷新页面/重开项目，历史仍在。

### 7.3 递归回滚

1. 选择第 2 步，确认「回滚到这一步之前」；
2. 检查第 2、3 步效果都消失，第 1 步保留；
3. 历史中第 2、3 步显示「已回滚」；
4. 备份目录仍存在。

### 7.4 归档

1. 回滚后先不做修改，确认历史仍显示已回滚；
2. 再做一次内容修改；
3. 旧的已回滚记录变为已归档，默认隐藏；
4. 新记录为 active，可回滚。

### 7.5 兼容

1. 旧调用 `content.rollback { backupDir }` 仍能恢复；
2. 旧项目没有 history 文件时，首次打开不报错。

## 9. 风险

| 风险 | 处理 |
| --- | --- |
| 逆序回滚部分失败 | 停止并报告，保留已完成状态和备份 |
| 历史文件与备份不同步 | history 写入失败时回滚资源；启动时校验备份存在 |
| 备份占用磁盘 | v0.2.1 不自动删；后续维护命令/设置页处理 |
| 回滚语义误解 | UI 固定文案「回滚到这一步之前」，确认框列出步数 |
| 输入修复影响现有配方 | 保存时解析，保持原 JSON 结构 |
