## 0. 摘要

对齐「用户能做的动作」与「agent 工具能做的动作」：补上内容资源、语言文件、素材、内容历史与项目维护，
让 agent 可以独立完成「新建物品 → 写配方/语言/模型 → 上传贴图 → 校验 → 导出」的闭环。

为避免工具数量膨胀，按领域合并为 4 个工具 + 1 个已有工具的扩展：

| 工具 | actions | 对应界面能力 |
| --- | --- | --- |
| `content`（新） | `get` / `preview` / `apply` / `history.list` / `history.rollback` | 物品编辑器的语言/配方/模型/标签；内容历史 |
| `lang`（新） | `list` / `preview` / `save` / `ensure` | 语言页：查看、保存、补建 |
| `asset`（新） | `list` / `upload` / `delete` / `model.get` / `model.save` | 贴图上传/删除、模型读写 |
| `project_admin`（新） | `reimport` / `add` / `saveMeta` / `setRoot` | 重新导入、添加已有项目、元数据、扫描根目录 |
| `workbench`（扩展） | 增加 `system.delete` / `task.delete` | 计划页删除系统卡/任务包 |

工具数 23 → 27；动作数不变（均为已有动作的业务函数转发，不新增 HTTP 动作）。

## 1. 未补齐的部分（有意保留）

| 动作 | 原因 |
| --- | --- |
| `assets.read` / `assets.readMany` | 返回 PNG data URL，agent 无法直接查看图片；需要时用 `asset.list` 看清单 |
| `project.open` / `projects.remember` | 会话/界面行为（打开项目、记住上次项目），工具直接按路径操作 |
| `guide` | 构建教程是 Markdown，agent 可直接读 `docs/BUILD-GUIDE.md` |
| `debug.clientGraph` | 仅诊断用，不属于用户动作 |

## 2. 工具行为

- `content.get` 返回回填结构，修改后传给 `content.apply`；`apply` 自动备份并记历史；
- `content.history.rollback` 默认 `toStep`，保留目标步、撤销其后；
- `lang.save` 只允许改已存在的键，空串删除；`lang.ensure` 补建旧项目缺失键；
- `asset.upload` 接收 PNG base64（不含 `data:` 前缀），仍校验 PNG/正方形/≤2MB；
- `project_admin.reimport` 需要 `project_analyze` 返回的 `proof`；
- `workbench` 的删除动作用 `system.id` / `task.id` 指定目标。

## 3. 验收

1. `content` 能回填、预览、应用并记历史，能回到某步；
2. `lang` 能列出、保存、补建缺失键；
3. `asset` 能上传、列清单、读写模型、删除贴图；
4. `project_admin` 能保存元数据、添加已导入项目、设置根目录、重新导入；
5. `workbench` 能删除系统卡与任务包；
6. 工具清单包含 4 个新工具且总数为 27；
7. 全量测试通过（20 文件 / 220 项）。
