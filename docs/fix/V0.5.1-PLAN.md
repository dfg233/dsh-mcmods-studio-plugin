# v0.5.1 计划：代码风格约束与标准结构（PATCH）

> 日期：2026-11-16
> 版本：v0.5.1（PATCH）

> 背景：v0.5.0 验收评价——「能够初步完成模组的代码编写工作，但仍存在 agent 代码写法不明确、项目结构不够标准的问题」。
> 风格基准：`D:/program/TutorialMod-1.20.1-Forge-master_2`（教程模组，已逐类分析）。

## 0. 摘要

v0.5.1 不改内容能力，只解决「写出来的代码像不像标准 Forge 模组」：

1. **标准结构**：scaffold 生成教程级项目骨架（注册类、`datagen/`、`client/` 分层），并写 `PROJECT-STRUCTURE.md`；
2. **风格约束**：把 TutorialMod 提炼的 12 条规则变成可检查项，`agent.validate` 输出风格问题；
3. **datagen 化**：资源 JSON 由 datagen provider 生成，模板提供 provider 片段，减少手写；
4. **原版参考**：新增 `mcmods_reference` 查询（CFR 反编译**项目构建依赖**的 mapped jar 源码 + `javap -p` 签名兜底；**不内置教程模组**），agent 写原版类似内容前先查实现。

## 1. 背景与依据

## 2. 目标与非目标

### 目标

- 新项目 scaffold 即生成标准骨架（含 `ModDataGenerator` 与 provider 空类）；
- agent 生成的代码可被 12 条规则检查，问题可定位到文件/行；
- 资源默认走 datagen（provider 片段模板），手写 JSON 仅作回退；
- agent 能查询 TutorialMod / Forge 源码中的对应实现。

### 非目标

- 不强制重构已有项目（只报告 + 给建议，不自动改）；
- 不引入 NeoForge / Fabric；
- 不改 `.mcstudio` 数据格式与现有动作语义；
- 不做完整代码格式化/静态分析器（只做结构/注册/资源级检查）。

## 3. 风格约束（12 条规则）

| # | 规则 | 教程依据 | 检查方式 |
| --- | --- | --- | --- |
| 1 | 主类只做集中注册与事件订阅；内容注册拆分到 `ModXxx`，每个提供 `register(IEventBus)` | `TutorialMod` 构造器 | 结构检查：主类中是否出现大量 `register` 调用、注册类是否存在 |
| 2 | 方块用 `registerBlock(name, supplier)` 自动注册 BlockItem；物品用 `ITEMS.register(id, supplier)` | `ModBlocks.registerBlock` | 静态检查：方块注册是否配套 BlockItem |
| 3 | 独立创造栏 `ModCreativeModeTabs`，`itemGroup.<tab>` 语言键，`displayItems` 收全量；不往原版标签注入 | `ModCreativeModeTabs` | 检查：每个物品是否在某个 tab 中、是否有 itemGroup 键 |
| 4 | 自定义 WoodType 必须带命名空间（`MOD_ID + ":ice_ether"`）；`Sheets.addWoodType` 在 client setup；**不手动注册 sign/hanging sign 模型层** | `ModBlocks.ICE_ETHER_WOOD_TYPE`、`TutorialMod.ClientModEvents` | 检查：WoodType name 是否含 `:`；是否出现 `createSignModelName` 手动注册 |
| 5 | 原版派生内容（船/告示牌）按原版逻辑：`hit.getLocation()`、`setYRot`、`noCollision(完整包围盒)`、`gameEvent`/`awardStat`，实体提供 `(Level,x,y,z)` 构造器 | `ModBoatItem`/`ModBoatEntity` | 检查：BoatItem 是否用 `getBlockPos()` 手工抬高；实体是否缺构造器 |
| 6 | 模型层集中 `entity/layer/ModModelLayers`，命名 `boat/<wood>`、`chest_boat/<wood>` | `ModModelLayers` | 结构检查 |
| 7 | 资源 JSON 由 datagen 生成：`BlockStateProvider`、`ItemModelProvider`、`LanguageProvider`、`RecipeProvider`、`BlockLootSubProvider` | `datagen/*` | 检查：`ModDataGenerator` 是否存在、`runs.data` 是否配置 |
| 8 | 资源目录固定：`assets/<modid>/textures/{block,item,entity,entity/signs,entity/signs/hanging,gui/hanging_signs,models/armor}`、`data/<modid>/{worldgen,dimension,tags}`、`data/minecraft/tags` | resources 目录树 | 结构检查 |
| 9 | 语言键规范：`itemGroup.<tab>`、`tooltip.<mod>.<item>`、`sounds.<mod>.<event>`、`entity.minecraft.villager.<mod>.<name>`；所有内容有键 | `ModEnUsLangProvider` | 检查：语言键缺失清单 |
| 10 | 世界生成用 `ModConfiguredFeatures` + `ModPlacedFeatures` + `ForgeBiomeModifiers`（`GenerationStep.Decoration`），由 datagen 产出 | `worldgen/*` | 检查：矿石/树是否走 BiomeModifier |
| 11 | `build.gradle`：ForgeGradle 6 + Parchment + `runs.data` + `sourceSets.main.resources { srcDir 'src/generated/resources' }` + `processResources` 占位符 | `build.gradle` | 检查：缺失项 |
| 12 | `gradle.properties` 固定键：`mod_id/name/license/version/group/authors/description`、`mapping_channel=parchment` | `gradle.properties` | 检查：缺失/非法值 |

- provider 模板：
  - `blockstate-provider`（simpleBlockWithItem / stairs / door / trapdoor / sign / hangingSign / log）；
  - `item-model-provider`（basicItem / handheldItem / simpleBlockItem）；

## 6. 风格检查器（P2）

- `agent.validate` 增加 `style` 区段：
  - `structure`：包/注册类/资源目录/`ModDataGenerator`/`runs.data`；
  - `naming`：id、字段、资源名、语言键；
  - `registration`：BlockItem 配对、创造栏覆盖、WoodType 命名空间、模型层重复；
  - `resources`：模型 parent、blockstate、语言键缺失；
- 分级：`error`（如 WoodType 无命名空间、模型层重复）/`warn`（缺 datagen、语言键缺失）/`info`（建议）；
- 阻断：`error` 级阻断 scaffold/生成，`warn`/`info` 仅提示（已确认）；
- 输出：文件路径 + 行号 + 规则编号（对应第 3 节 12 条）。

## 7. 原版参考（P4，已确认方案）

**结论（2026-11-16 实测）**：ForgeGradle 6 **没有** `genSources`/`decompileJar`/`sourcesJar` 任务；mapped jar 只有 `.class`（无源码）。要获得可被 agent 读取的 Java 源码，采用 **CFR 反编译**：

- 反编译器：**CFR 0.152**（单 jar，约 2.1MB，Apache 2.0）；
- 输入：项目 `minecraft_user_repo` 下的 `forge-<ver>_mapped_parchment_<mapping>.jar`；
- 输出：反编译 `.java` 到插件缓存目录（首次整包约几分钟、5453 文件 / 27.1MB；之后按类读取），实测 `BoatItem.java` 方法体完整可读；
- 可读性说明：**方法参数**来自 Parchment（`pLevel`/`pPlayer`），**方法内局部变量**因官方 jar 无 `LocalVariableTable` 只能是 `$$N` 占位（Parchment 不映射局部变量，属数据边界，不影响理解）；
- 兜底：第三方库无源码时用 `javap -p` 返回签名；`javap -c` 字节码仅在必要时使用。

工具与接口：

- 新工具 `mcmods_reference`（或 `workbench` 的 `reference.*` 动作）：
  - `search { query }`：按类名/方法/关键字返回匹配；
  - `get { className }`：返回反编译源码片段（截断 + 文件:行号）或签名；
  - 索引源：**项目自身 Gradle 依赖**（`minecraft_user_repo` 的 mapped jar、第三方 `sources.jar`）+ CFR 反编译缓存；**不内置教程模组**（TutorialMod 仅作为插件制作阶段的风格基准，不打包、不索引）；
- 缓存目录：`$DSH_HOME/mcmods-studio/cache/reference/<projectHash>/`（反编译产物，可删除重建）；
- 约束：只读、不复制到项目、返回标注来源（文件:行号）；CFR 随插件分发或首次使用时下载（校验 sha256）。

## 11. 风险

| 风险 | 应对 |
| --- | --- |
| 检查器误报/过严 | error 只对确定性问题（命名空间、重复层）；其余 warn |
| datagen 与用户手写资源冲突 | 检查 generated 与 main 资源重名；提示优先 datagen |
| 旧项目迁移成本 | 只报告不重构；提供「问题清单 + 建议」 |
| CFR 反编译体积/耗时 | 缓存约 27MB/项目，按类读取；可删除重建；首次反编译后台执行 |

## 12. 已确认的决策（2026-11-16）

1. **风格检查阻断**：`error` 级问题阻断 scaffold/生成（如 WoodType 无命名空间、模型层重复）；`warn`（缺 datagen、语言键缺失）仅提示；
2. **旧项目**：只报告问题清单与建议，不自动改（ice_ether 作为量化样例，不自动重构）；
3. **参考源**：CFR 反编译**项目构建依赖**的 mapped jar（源码）+ `javap -p` 签名兜底；**不内置/不打包教程模组**；
4. **datagen 化**：新项目默认开启（scaffold 生成 `ModDataGenerator` 与 providers），可关闭。
