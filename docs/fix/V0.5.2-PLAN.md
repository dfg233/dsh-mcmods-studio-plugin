# v0.5.2 计划：形态归并、素材预览与失效项目清理（PATCH）

> 日期：2026-11-16
> 版本：v0.5.2（PATCH）
> 状态：**方案待确认，未实现**
> 关联：[V0.5.1-PLAN.md](V0.5.1-PLAN.md)、[PROJECT-STRUCTURE.md](../design/PROJECT-STRUCTURE.md)
> 来源：v0.5.1 验收反馈的 3 个缺陷（不改变内容能力）。

## 0. 摘要

1. **形态归并**：门的上下半、作物的生长阶段等「同一物品的不同形态」不再识别成多个独立物品；
2. **素材预览**：资源页按游戏内方式显示——物品用 item model 合成 2D 贴图，方块用 blockstate/模型解析后做等轴渲染；
3. **失效项目**：项目页不再常驻显示已删除目录；测试与清理动作一并注销注册表条目。

## 1. 缺陷与根因

### 1.1 形态被拆成独立物品

- 根因：`lib/import.js` 的 `blockIds = blockstates ∪ blockModels ∪ blockTextures`（见 `import.js` 约 513 行），把 `*_top`/`*_bottom`/`*_stageN`/`*_head`/`*_foot` 等部件名当成独立方块；
- 表现：门出现「门本体 / 上半门 / 下半门」三条；作物出现每个生长阶段一条；
- 影响：物品清单膨胀、创造栏与资源对应关系混乱。

### 1.2 素材页显示的是贴图文件本身

- 现状：`client.js` 的 `AssetsTab` 每个条目读一张 `textures/item|block/<id>.png`，方块只显示主贴图，物品只显示 layer0；
- 目标：物品按 item model 的 layer 叠加显示 2D；方块按 blockstate 解析出的面/贴图做等轴（top/left/right 三面）预览；
- 已有基础：`assets.blocks` 已包含 `faces`/`textures`/`uniform`/`primaryKind`（方块解析），`ItemsTab` 已有 `thumbKey` 主贴图逻辑可复用。

### 1.3 项目页显示已删除目录

- 根因：`boot` 的 `projects` 对每个注册项做 `missing: !exists`（`api.js` 约 213 行），但 UI 未过滤/折叠；测试 `project.create` 后只删目录、不清注册表（`test/helpers.mjs` 的 `cleanup` 只 `rm` 目录）；
- 表现：测试跑完后「项目」页常驻一批已删除目录的条目。

## 2. 目标与非目标

### 目标

- 导入识别阶段归并形态，条目数不随变体膨胀；
- 资源页按游戏内方式预览贴图（物品 2D、方块等轴）；
- 项目页不再显示失效目录；测试自动注销；提供一次性清理动作。

### 非目标

- 不改已有项目的条目数据（只影响新导入；老项目可手动重新扫描）；
- 不做完整 3D 渲染器/材质光照（等轴预览用 CSS/Canvas 合成即可）；
- 不引入新依赖（无 three.js 等）。

## 3. 形态归并（缺陷 1）

### 3.1 归并规则

| 类别 | 归并键 | 归并后保留 |
| --- | --- | --- |
| 门 | `<wood>_door` | `door_top`/`door_bottom` 贴图与状态列表 |
| 活板门 | `<wood>_trapdoor` | `trapdoor_top`/`trapdoor_bottom`/`trapdoor_open` |
| 作物 | `<crop>` | `stage0..N` 模型与贴图 |
| 床 | `<color>_bed` | `bed_head`/`bed_foot` 状态 |
| 告示牌 | `<wood>_sign` / `<wood>_hanging_sign` | wall 变体归并到本体 |
| 栅栏门/墙 | `<wood>_fence_gate` / `<wood>_wall` | `fence_gate_open` 等状态 |

### 3.2 实现要点

- `import.js` 在 `blockIds` 生成后做一次「部件 → 父 id」归并：`stripSuffix` 列表（`_top`、`_bottom`、`_head`、`_foot`、`_inner`、`_outer`、`_corner`、`_stage<N>`、`_open`、`_wall` 按类别处理）；
- 归并结果写入 `assets.blocks[].variants`（保留被归并的部件名，供资源页/模型编辑使用）；
- `assets.list` 的 `blocks` 返回归并后的 id；`missing` 检查按归并后 id 计算；
- 已导入项目不动数据；新增 `assets.rescan`（可选，用户手动触发）重新归并。

## 4. 素材预览（缺陷 2）

### 4.1 物品（2D）

- 前端读 `models/item/<id>.json` 的 `textures.layer0..layerN`（`item/generated` 支持多层）；
- 按顺序叠加显示（CSS `position:absolute` 或 Canvas 合成），无模型时回退 `textures/item/<id>.png`；
- `handheld`/`block` 模型回退到对应贴图。

### 4.2 方块（等轴）

- 用 `assets.blocks[].faces`（top/left/right）+ `textures` 读取三张贴图，前端用 CSS 3D 变换拼等轴立方体（top 菱形 + 两侧面），或 Canvas 预计算；
- `uniform` 方块用单贴图 + 明暗遮罩；无 blockstate 时回退磨砂方块 + 单贴图。

### 4.3 接口

- `assets.readMany` 扩展返回 `models`（layers/faces），或新增 `assets.preview`（返回渲染所需的贴图集合与层信息）；
- 缩略图按 64px 缓存（Map by `kind/id`），不重复请求。

## 5. 失效项目（缺陷 3）

- `boot` 返回 `projects` 保持 `missing` 标记；前端「项目」页默认隐藏 `missing`，并显示「失效 N 个」折叠区 + 「清理」按钮；
- 新增 `project.prune` 动作：删除所有 `missing` 的注册项（不删磁盘），返回清理数量；
- `test/helpers.mjs`：`cleanup` 时遍历本工作区创建的项目（记录 `project.create` 的路径）并调用 `forgetProject`；`runSuite` 结束统一清理；
- `scripts/benchmark.mjs` 已有 `forgetProject`，保留；
- 一次性清理：提供 `project.prune`，本次发版前对当前注册表执行一次（记录清理数量）。

## 6. 接口与工具变更

- 新增动作：`project.prune`（+1 → 130）；`assets.preview`（可选，+1 → 131）；
- `assets.readMany` 扩展字段（向后兼容）；
- 无新工具（复用 `project` / `asset` 工具的动作）。

## 9. 风险

| 风险 | 应对 |
| --- | --- |
| 归并误伤（如 `*_stairs` 以 `_s` 结尾被误判） | 只按明确后缀表匹配；先跑 fixture 验证 |
| 归并后旧项目资源路径变化 | 只影响新导入；旧项目提供 rescan 且不自动改 |
| 等轴预览性能 | 64px 缩略图 + 缓存；只读已解析 faces |
| UI 改造破坏现有页面 | 保持组件接口，逐步替换缩略图渲染 |
