# v0.4.2 计划：MDK 模式（下载官方 MDK / 本地 MDK）

> 日期：2026-11-07
> 版本：v0.4.2（PATCH）
> 状态：**已实现、已发版（0.4.2，2026-11-07）**
> 关联：[V0.4.0-ISSUES-REPORT.md](V0.4.0-ISSUES-REPORT.md)、[V0.4.0-PLAN.md](../major/V0.4.0-PLAN.md)、[DATA-FORMAT.md](../DATA-FORMAT.md)
> 决策来源：2026-11-07 用户确认——**默认下载官方 MDK**（按矩阵固定推荐版本）；次选本地 MDK（zip / 已解压目录）；**内置模板不推荐**，仅在用户显式选择时启用。

## 0. 摘要

v0.4.1 的工程生成使用**插件内置模板**（`templates/scaffold/`）。内置模板离线稳定，但与官方 MDK 存在滞后，且需要插件随 MC/loader 升级维护。

v0.4.2 把默认路径改为 **MDK 模式**：

1. **下载官方 MDK（默认）**——按版本矩阵固定「官方推荐版本」，仅白名单源；下载、校验后交给构建流程；
2. **本地 MDK（次选）**——用户提供 zip 或已解压目录；校验、解压、替换变量、生成完整工程；
3. **内置模板保留为兜底**——仅在用户显式选择时启用，UI 标注「不推荐，可能与官方 MDK 有滞后」。

MDK 模式的核心不是「解析整个 Gradle 脚本」（MDK 版本间差异大），而是：

- **识别**：从 `gradle.properties` / `build.gradle` / `settings.gradle` / 描述文件读取 loader 与 MC 版本；
- **替换**：在 MDK 副本上做**受控变量替换**（modid、名称、版本、作者、license、包名、主类），替换后校验无残留占位符；
- **校验**：生成后检查必需文件与关键字段，结构刷新 + 基础检查；
- **回滚**：任何一步失败删除本次产物，不破坏用户已有目录。

## 1. 目标与非目标

### 目标

- 新建项目时可选择「MDK」来源：默认下载官方 MDK，次选本地 zip / 已解压目录；
- 生成结果与官方 MDK 一致（保留 `gradlew`、wrapper、runs、publishing 等原样内容）；
- 只替换插件需要修改的字段，其余保持 MDK 原样；
- 全流程可预览、可回滚、有明确错误信息；
- 离线可用（用户提供 MDK 时插件不联网）。

### 非目标（v0.4.2 不做）

- 不做「任意创意工坊 zip 导入」（那是 `project.import` 的职责）；
- 不解析/改写 MDK 的 `build.gradle` 逻辑（只替换已知占位符与少量文本）；
- 不自动升级 MDK 或迁移旧工程；
- 不在生成时默认运行 `gradlew`（编译验证需显式开启，见 §7）。

## 2. 用户流程

### 2.1 新建项目（GUI）

```text
新建模组项目
├─ 项目目录：[浏览…]
├─ 项目名称：My Mod          （可中文，Gradle 英文名自动派生 / 可编辑）
├─ modid：mymod
├─ 加载器：Forge / NeoForge / Fabric
├─ MC 版本：1.20.1（当前版本矩阵）
├─ 工程来源：
│   (●) 下载官方 MDK（推荐，默认）
│       ├─ 自动使用矩阵版本：Forge 47.4.16 · Minecraft 1.20.1
│       └─ [下载并创建]（下载前确认 URL 与版本）
│   ( ) 使用本地 MDK（zip / 已解压目录）
│       └─ 解析结果：Forge 47.4.16 · Minecraft 1.20.1 ✓
│   ( ) 使用内置模板（不推荐，仅离线兜底）
└─ [创建]
```

- 选择 zip/目录后立即调用 `scaffold.inspect` 展示 loader/MC/loader 版本与警告；
- 版本与矩阵不符时禁用「创建」并说明原因；
- 「让 AI 下载」需要用户确认来源与版本（agent 走 `scaffold.download`）。

### 2.2 agent 流程

```text
scaffold.download{ loader, minecraft, into } → 下载官方推荐 MDK → 交给 apply（默认路径）
scaffold.inspect { path }                  → 识别 loader / MC / 版本（本地 MDK）
scaffold.preview { source:'mdk', archive|dir, params } → 文件清单与替换项、冲突
scaffold.apply   { source:'mdk', archive|dir, params, requestId } → 生成 + 备份 + 校验
```

### 2.3 失败与回退

| 场景 | 行为 |
| --- | --- |
| zip 无效 / 路径穿越 / 超大 | 拒绝，返回明确错误；不落盘 |
| zip 与目标 loader/MC 不符 | 拒绝，提示实际版本与矩阵 |
| 目标目录非空 | 默认拒绝；`allowMerge: true` 时只写缺失文件并报告冲突 |
| 替换后仍有 `${...}` 占位符 | 拒绝（防止生成半成品） |
| 生成后校验失败 | 删除本次产物，恢复备份 |
| 下载失败 / 网络不可用 | 提示改用「本地 MDK」或稍后重试；不自动回退内置 |
| MDK 不可用且用户未选内置 | 提示下载或选择本地 MDK；不自动回退内置 |

## 3. 实现方案

### 3.1 新增模块 `lib/mdk.js`

职责：**识别、安全解压、受控替换、校验、回滚**，不直接暴露 HTTP。

#### 3.1.1 识别 `inspectMdk(source)`

输入：zip 路径或目录路径。
输出：

```json
{
  "kind": "forge | neoforge | fabric",
  "minecraft": "1.20.1",
  "loaderVersion": "47.4.16",
  "hasWrapper": true,
  "hasGradle": true,
  "files": 42,
  "warnings": ["..."],
  "errors": []
}
```

识别规则（按优先级）：

1. `src/main/resources/fabric.mod.json` 存在 → `fabric`（MC 从 `gradle.properties` 的 `minecraft_version` 或 `fabric.mod.json` 的 `depends.minecraft` 读）；
2. `gradle.properties` 含 `forge_version` → `forge`；含 `neo_version` → `neoforge`；
3. `build.gradle` 含 `forgegradle` / `net.neoforged.gradle` / `fabric-loom` 插件 → 对应 loader；
4. 无匹配 → `errors: ['无法识别加载器']`。

版本一致性：与 `lib/version-matrix.js` 比对；不在矩阵内 → `errors` 带上可用组合。

#### 3.1.2 安全解压 `extractMdkArchive(zipPath, targetDir)`

- 用 Node 内置能力（`node:zlib` 的 `inflateRaw` + zip 中央目录解析）或引入轻量依赖；**不使用系统 `unzip`**（避免平台差异）；
- 逐条检查：
  - 拒绝绝对路径（`/` 开头、`C:\`、`\\server\`）、含 `..` 的路径；
  - 拒绝符号链接/硬链接条目；
  - 拒绝超出目标目录的路径（`resolve` 后 `startsWith` 校验）；
  - 文件数上限（默认 20000）、解压后总大小上限（默认 256MB）、单文件上限（默认 64MB）；
  - 不递归解压嵌套 zip；
- 先解压到 `<目标>/.mcstudio/tmp/mdk-<id>/`，成功后原子移动到目标目录；失败删除临时目录。

#### 3.1.3 受控替换 `applyMdkParams(mdkDir, params)`

只改以下位置，其余保持原样：

| 文件 | 替换项 |
| --- | --- |
| `gradle.properties` | `mod_id` / `mod_name` / `mod_license` / `mod_version` / `mod_group_id` / `mod_authors` / `mod_description`（值按 v0.4.1 规则：Gradle 字段 ASCII） |
| `src/main/resources/META-INF/mods.toml` | `modId` / `displayName` / `version` / `authors` / `description` / `license`（若为 `${...}` 占位则由 Gradle 展开，不改；若为字面值则替换） |
| `src/main/resources/fabric.mod.json` | `id` / `name` / `version` / `authors` / `description` / `license` |
| 主类（`*Mod.java` / `Main.java` 等） | 包声明、类名（由 `params.package` / `ClassName` 决定），并按新包路径移动文件 |
| `settings.gradle` | `rootProject.name`（若存在） |
| `gradle.properties` 的 `archives_base_name`（fabric） | modid |

替换规则：

- 使用精确 key 替换（`key=value`），不做全局文本替换；
- 替换后扫描目标文件，若仍含 `${mod_id}` / `{{...}}` 等未展开占位符 → 报错；
- 主类识别：`src/main/java/**` 下含 `@Mod(` 或 `extends ModInitializer` 的类；找不到 → 警告（不阻塞，但 UI 提示「未找到主类」）；
- 包名替换：把主类的 `package` 行改成 `{{package}}`，文件移动到 `packagePath`。

#### 3.1.4 校验 `validateMdkOutput(projectPath, params)`

生成后检查：

- `build.gradle` / `settings.gradle` / `gradle.properties` / `gradlew` / `gradlew.bat` 存在；
- `gradle.properties` 的 `mod_id` 与参数一致；
- `mods.toml` 或 `fabric.mod.json` 存在且 `id` 正确；
- 主类存在且 `package` 与目录一致（找不到主类只警告）；
- 无残留 `${...}` 占位符（允许 MDK 自带的、由 Gradle 展开的占位符，需白名单：`${mod_id}` 等在 `processResources` 中展开的属正常——因此「残留占位符」检查只针对**插件替换过的字段**）。

### 3.2 版本矩阵扩展 `lib/version-matrix.js`

新增 MDK 来源信息（供下载与提示，不影响内置模板）：

```js
mdk: {
  forge:    { url: 'https://maven.minecraftforge.net/net/minecraftforge/forge/{mc}-{loader}/forge-{mc}-{loader}-mdk.zip' },
  neoforge: { url: 'https://maven.neoforged.net/releases/net/neoforged/neoforge/{loader}/neoforge-{loader}-mdk.zip' },
  fabric:   { url: 'https://github.com/FabricMC/fabric-example-mod/archive/refs/tags/{mc}.zip' },
}
```

- 下载只允许上述域名（白名单），HTTPS；
- 可选 `sha256` 校验（官方 MDK 无公开校验和，记录实际 sha256 供审计）。

### 3.3 API 动作（`lib/api.js`）

新增（`scope: 'none'` 或 `'studio'` 视动作）：

| action | payload | 返回 |
| --- | --- | --- |
| `scaffold.inspect` | `{path}`（zip 或目录） | `{kind, minecraft, loaderVersion, files, warnings, errors}` |
| `scaffold.preview`（扩展） | `{source:'mdk', archive?, dir?, params, allowMerge?}` | `{params, files[], conflicts[], warnings[]}` |
| `scaffold.apply`（扩展） | `{source:'mdk', archive?, dir?, params, requestId, verifyBuild?}` | `{params, files[], created[], backupDir, warnings[], buildVerified}` |
| `scaffold.download` | `{loader, minecraft, into, requestId}` | `{path, url, sha256, bytes, kind, minecraft}` |

- `source` 默认 `'builtin'`（保持 0.4.1 兼容）；`'mdk'` 时必须有 `archive` 或 `dir`；
- 旧的 `scaffold.preview/apply` 参数不变，行为不变（内置模板）；
- `scaffold.download` 默认可用（MDK 是默认路径）：每次下载前需用户确认，仅白名单主机，记录 URL 与 sha256；可在设置中关闭。

### 3.4 Agent 工具（`lib/tools.js`）

`scaffold` 工具扩展参数：

```json
{
  "action": "preview | apply | inspect | download",
  "source": "builtin | mdk",
  "archive": "D:/downloads/forge-1.20.1-47.4.16-mdk.zip",
  "dir": "D:/downloads/forge-mdk",
  "into": "D:/downloads",
  "loader": "forge",
  "minecraft": "1.20.1",
  "params": { "modid": "mymod", "name": "My Mod", "package": "com.example.mymod" },
  "allowMerge": false,
  "verifyBuild": false
}
```

工具描述明确：**MDK 模式优先；内置模板不推荐**。

### 3.5 新建项目弹窗（`client.js`）

- 「工程来源」radio（默认第一项）：`下载官方 MDK（推荐）` / `使用本地 MDK` / `使用内置模板（不推荐）`；
- 下载 MDK 子表单：显示矩阵版本（Forge 47.4.16 · MC 1.20.1），[下载并创建] 前弹确认框（URL、版本、白名单提示）；
- 本地 MDK 子表单：选择 zip / 目录 → 调 `scaffold.inspect` 显示解析结果或错误；
- 创建时 `project.create` 增加 `source` / `archive` / `dir` 参数，透传给 `scaffold.apply`；
- 内置模板选项旁标注「离线兜底，可能与官方 MDK 有滞后」。

### 3.6 与现有流程的关系

- `project.create { scaffold: true }` 保持不变（默认内置，兼容 0.4.1）；
- 新增 `project.create { scaffold:'mdk', archive|dir }` 或 `scaffold:true, source:'mdk'`；
- 生成后仍走 `refreshStructure` / `rebuildSummary`，后续模板、codegen、任务流程不变。

## 4. 保障措施（重点）

### 4.1 安全

| 风险 | 措施 |
| --- | --- |
| zip 路径穿越 | 拒绝绝对路径、`..`、UNC；解析后 `resolve` 校验仍在目标目录内 |
| 符号链接 / 硬链接 | 拒绝该类 zip 条目 |
| zip 炸弹 | 文件数 ≤ 20000、解压总大小 ≤ 256MB、单文件 ≤ 64MB、不递归嵌套 zip |
| 覆盖用户文件 | 目标目录非空默认拒绝；`allowMerge` 只写缺失文件并报告冲突 |
| 执行恶意脚本 | 不执行 MDK 内任何脚本；`gradlew` 仅复制；编译验证显式开启 |
| 下载源不可信 | 主机白名单（仅官方 maven / GitHub FabricMC）、HTTPS、记录 URL 与 sha256 |
| 大文件内存占用 | 流式解压/下载，不把整个 zip 读进内存 |

### 4.2 正确性

- 识别失败、版本不匹配、必需文件缺失 → 明确错误，不生成半成品；
- 替换只作用于已知 key，不全局替换；
- 替换后校验关键字段（`mod_id`、`id`、`mods.toml`/`fabric.mod.json`）；
- 主类包名/目录一致性校验；
- 生成后自动 `structure.refresh`，并可选跑 `validate`。

### 4.3 可恢复

- 目标已存在且允许合并时，先备份（复用 `backupContentFiles`/`restoreContent`）；
- 解压/替换/校验任一步失败：删除本次产物 + 恢复备份；
- 返回 `backupDir`，支持后续回滚（与内容历史一致）。

### 4.4 可观测

每次操作返回：`source`（`mdk-user` / `mdk-download` / `builtin`）、`files`、`warnings`、`errors`、`backupDir`、`sha256`（下载时）。
UI 展示：解析结果、替换项、冲突、错误。

## 7. 已确认的决策（2026-11-07）

1. **优先级**：默认「下载官方 MDK」；次选「本地 MDK」；内置模板仅作离线兜底，不推荐。
2. **下载白名单**：只允许 `maven.minecraftforge.net`、`maven.neoforged.net`、`github.com/FabricMC` 三个域名（HTTPS）。
3. **目标目录非空**：默认拒绝；不提供自动合并（如未来需要再评估 `allowMerge`）。
4. **编译验证**：`verifyBuild` 默认关闭，由用户显式勾选。
5. **MDK 版本**：使用矩阵固定「官方推荐版本」（Forge 47.4.16 / Neo 47.1.106 / Fabric loader 0.15.11），下载时只允许这些版本。
6. **下载开关**：`scaffold.download` 默认可用（默认路径），每次下载需用户确认；设置中可关闭。
7. **本轮不写代码**：先更新文档；实施待你确认开工。

## 8. 风险

- **MDK 变体差异**：不同版本 MDK 的 `gradle.properties` key 与主类位置不同 → 用「识别 + 已知 key 替换 + 校验」降低风险，无法识别时明确报错；
- **网络受限**：下载为默认路径，本地 MDK 为离线备选；下载失败时明确提示，不自动回退内置；
- **大文件/耗时**：上限 + 进度提示（P3 后再加进度）；
- **zip 解析实现成本**：若不想引入依赖，可先支持「已解压目录」，zip 支持放在 P1 后半段（用最小 zip 解析器，只读中央目录）。
