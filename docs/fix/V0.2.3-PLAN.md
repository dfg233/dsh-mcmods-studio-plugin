## 0. 摘要

本次优化处理三件事，均不改变现有物品数据与资源文件格式：

1. **物品编辑界面分页**：把一整页长表单按内容类型拆成 5 个页签；语言并入「基础」，属性页暂不再拆（后续版本再拆子页）。
2. **工作台语言页**：新增「语言」页签，集中展示并编辑项目全部物品的语言键（`zh_cn` / `en_us`），支持筛选、行内编辑、缺失提示与批量保存。
3. **语言键生命周期**：语言键跟随物品创建与删除——创建物品时连带创建，删除物品时连带删除；语言页不允许新增任意键或修改未知键。

所有对语言文件的写入（语言页保存、创建/删除连带、补建缺失键、改名迁移）都走统一的备份与内容历史。

## 1. 现状

### 1.1 物品编辑器（`ItemEditor`）

- 单文件 `client.js` 内的一个 `Modal`，宽度 `min(760px, 92vw)`，全部字段同屏：
  - 注册名、显示名、类型、贴图、描述；
  - 语言（中文名 / 英文名）；
  - 配方（类型、产出、Pattern、材料键、材料、经验、烧炼时间）、资源标签、物品模型；
  - 19 个属性字段（按「基础属性 / 数值属性 / 行为属性 / 标签属性 / 兼容性」五组）；
  - 自定义标签、备注。
- 内容较多时需要长距离滚动；语言与配方混在「语言与配方」一节，后续再加方块属性、战利品表等会继续膨胀。
- 保存/取消在 `Modal` footer，与页面内容无关，分页不会影响提交逻辑。

### 1.2 语言文件与现有行为

- 位置：`src/main/resources/assets/<modid>/lang/zh_cn.json` 与 `en_us.json`；工程没有标准资源目录时回退到 `.mcstudio/assets/<modid>/lang/`（`lib/assets.js` 的 `resolveAssetRoot`）。
- 键格式：物品 `item.<modid>.<id>`，方块 `block.<modid>.<id>`（`lib/content.js` 的 `langKeyFor`）。
- 现有写入：`content.apply` 只处理**当前物品**的两条语言键，按「读当前文件 → 合并单键 → 写回」的方式保留其他键；**物品创建与删除不会维护语言键**，因此新物品可能没有语言键、删除物品会留下旧键。
- 现有读取：`content.get` 只返回当前物品的 `lang.zh` / `lang.en`；没有「项目级语言总览」。
- 语言文件可能包含其他模组或手写的键（合并型文件），这些键必须原样保留。

### 1.3 可复用的能力

| 能力 | 位置 | 复用方式 |
| --- | --- | --- |
| 资源根解析 | `lib/assets.js` 的 `resolveAssetRoot` | 语言页直接使用，保证标准/回退路径一致 |
| 原子写 JSON | `lib/registry.js` 的 `writeJson` | 语言文件写入复用 |
| 内容备份 | `lib/content.js` 的 `createBackup`（内部） | 导出为 `backupContentFiles`，语言写入复用同一 manifest 格式 |
| 恢复与校验 | `lib/content.js` 的 `restoreContent` | 已导出；语言写入失败时恢复 |
| 内容历史 | `lib/history.js` 的 `appendHistoryEntry` | 语言写入记一步历史；新增可选 `scope` 字段 |
| 页签组件 | `client.js` 的 `Tabs` | 物品编辑器分页与工作台页签共用 |

## 2. 目标与非目标

**目标**

- 物品编辑器可按内容类型切换页签，字段不再全部堆在一屏；语言在「基础」页内编辑；
- 新增语言页，能一次看到所有物品的中英文与缺失情况，并批量修改保存；
- 语言键随物品创建/删除自动维护，旧项目可一次性补建缺失键；
- 语言写入只改语言文件，保留未知键，写前备份、失败回滚、记入内容历史；
- 历史记录能区分「物品级」与「项目级（语言）」，并可回滚语言步骤；
- 不改变 `.mcstudio/items`、语言文件键格式与已有资源文件路径。

**非目标**

- 不做多语言（除 `zh_cn` / `en_us` 之外的 locale）；
- 不做自动翻译或调用模型补英文；
- 不允许在语言页新增任意键（包括其他模组键、手写键）；
- 不自动清理「未知键」或改名后遗留的旧键（只读展示，删除需人工处理）；
- 不把物品属性改造成可拖拽/自定义布局；属性页本期不拆子页；
- 不做物品编辑器到语言页的跳转（语言已在基础页内编辑）；
- 不做跨项目的语言汇总。

## 3. `FEAT-01` 物品编辑界面分页

### 3.1 页签划分（5 页）

| 页签 | 包含内容 | 数据来源 |
| --- | --- | --- |
| **基础** | 注册名、显示名、类型、贴图上传、**中文名、英文名**、描述 | `draft` 顶层 + `imageFor` + `content.lang` |
| **属性** | 19 个字段，按「基础属性 / 数值属性 / 行为属性 / 标签属性 / 兼容性」小节分组 | `schema.fields` |
| **配方** | 配方类型、产出数量、Pattern、材料键、材料、经验、烧炼时间 | `content.recipe` |
| **标签** | 物品标签、方块标签（`properties` 中的 tags 字段）、资源标签（`data/*/tags`）、自定义标签 | `draft.properties` + `content.tagsText` + `draft.tags` |
| **模型与备注** | 物品模型（generated / handheld）、备注 | `content.model` + `draft.notes` |

说明：

- 语言按决策并入「基础」：中文名、英文名紧跟在「显示名」之后，避免与「描述」混淆；
- `loaderNotes` 属于「兼容性」组，留在「属性」页；
- 属性页本期保持一页，五组按小节渲染；后续版本再把五组拆成子页签（不在本期）；
- 「模型与备注」不包含描述（描述在基础页），避免重复。

### 3.2 交互规则

1. 打开编辑器默认停在「基础」页。
2. 切换页签不提交、不重置任何输入；`draft` 与 `content` 状态始终在同一组件内。
3. 保存/取消按钮固定在 footer，任何页都可保存；保存 payload 与现在完全一致。
4. 切换页签时弹窗滚动位置回到顶部（`modalBody` 的 `scrollTop = 0`）。
5. 离开编辑器仍由现有草稿逻辑提示（`useDraftState` 的 dirty + beforeunload）。
6. 校验提示（id 非法、数值越界）仍在字段旁显示；本期不在页签上加红点。
7. 不做「在语言页中编辑」跳转；基础页内直接编辑语言，保存时仍由 `content.apply` 写入。

### 3.3 实现方法（`client.js`）

1. `ItemEditor` 内新增 `const [page, setPage] = useState('basic')`。
2. 定义页签常量：
   ```js
   const PAGES = [
     { id: 'basic', label: '基础' },
     { id: 'attributes', label: '属性' },
     { id: 'recipe', label: '配方' },
     { id: 'tags', label: '标签' },
     { id: 'extra', label: '模型与备注' },
   ]
   ```
3. 在 Modal body 顶部渲染页签条：
   - 复用 `Tabs`，新增 `props.style` 支持，或新增 `S.modalTabs`（`display:flex; gap:4px; padding:0 0 10px; borderBottom: 1px solid C.border; marginBottom: 12; overflowX:auto`）。
   - 页签条位于「已恢复上次未保存的草稿」提示之下。
4. 把现有 JSX 按页拆成条件渲染：
   - `renderBasicPage()`：id / 显示名 / 类型 / 贴图 / 中文名 / 英文名 / 描述；
   - `renderAttributesPage()`：复用现有 `groups` + `renderField`；
   - `renderRecipePage()`：配方类型 + 产出 + 动态子表单（shaped / shapeless / furnace）；
   - `renderTagsPage()`：schema 中 `type === 'tags'` 的字段 + 资源标签 + 自定义标签；
   - `renderExtraPage()`：模型选择 + 备注。
   - 首版可内联 `switch`，稳定后再拆成子组件（拆分时把 `draft`、`content`、`set`、`setRecipe` 等作为 props 传入）。
5. 保持 `content.get` 的 effect 依赖不变，切换页签不会重新请求。
6. 保存逻辑不变：`contentPayload(content)` + `props.onSave(draft, payload)`。

### 3.4 测试影响

- 现有 `test/12-render.mjs` 的「物品编辑器渲染分组与字段」一次断言所有字段同屏，分页后会失败，需要拆成：
  1. 默认渲染「基础」页：注册名、显示名、类型、贴图、中文名、英文名、描述；
  2. 点击「属性」页签后渲染五组与字段；
  3. 点击「配方」页签后渲染 Pattern / 材料键；
  4. 切换页签后输入值仍在（fake React 中调用输入框 `onChange` → 切页 → 重渲染断言）。

### 3.5 后续可扩展的专属功能

| 页签 | 后续功能 |
| --- | --- |
| 基础 | 贴图拖放上传、id 改名冲突提示、语言缺失提示 |

### 3.6 验收

1. 打开编辑器默认停在「基础」页，字段不再全部同屏；
2. 五个页签可切换，切换后已填内容不丢失；
3. 中文名、英文名在「基础」页可编辑；
4. 任意页保存，生成的 JSON 与改造前一致（字段、顺序、默认值不变）；
5. 草稿恢复后仍能正常编辑与保存；
6. 全量测试通过（新增或调整的渲染用例计入）。

| 风险 | 处理 |
| --- | --- |
| 现有渲染测试依赖「全字段同屏」 | 同步调整测试，按页断言 |

## 4. `FEAT-02` 工作台语言页

### 4.1 数据范围与键规则

- 语言文件：`zh_cn.json`、`en_us.json`，位置由 `resolveAssetRoot` 决定；
- 参与展示与编辑的键：
  - 物品：`item.<modid>.<id>`，`id` 来自 `.mcstudio/items/*.json`；
  - 方块：`block.<modid>.<id>`，物品条目 `type === 'block'`；
  - 其他键（其他模组、手写、已删除物品的旧键）：归入「其他键」，只读展示，不可编辑、不可删除；
- 不处理 `creative_tab` 类型条目的语言键（现有内容编辑也未处理），在页面底部说明。

### 4.2 语言键生命周期（`FEAT-03`）

| 时机 | 行为 | 写入方式 |
| --- | --- | --- |
| 创建物品（`items.save` 新建） | 自动创建该物品的 `zh_cn` 与 `en_us` 键 | 走统一语言写入事务：备份 + 写文件 + 记历史 |
| 修改物品（`items.save` 更新，id 不变） | 不自动改语言值；语言值仍由物品编辑器/语言页显式编辑 | 与现有 `content.apply` 一致 |
| 修改 id（改名） | 迁移语言键：删除旧键、创建新键（沿用旧值） | 备份 + 写文件 + 记历史；迁移失败保留旧键并返回 warning |
| 删除物品（`items.delete`） | 删除该物品两个 locale 的键 | 备份 + 写文件 + 记历史；语言文件不存在时跳过 |
| 旧项目缺少键 | 语言页显示「缺少语言键」，提供「补建缺失键」按钮 | 等价于创建时连带创建；备份 + 历史 |

取值规则（创建时）：

- `en_us`：取 `displayName`；`displayName` 为空时留空；
- `zh_cn`：默认取 `en_us` 的值（即「用英文填补空缺」，见决策 7）；若用户在物品编辑器里已填中文名，以用户值为准；
- 两个值都为空时仍创建空键（占位），便于语言页显示与后续填写。

说明：

- 「英文填补空缺」只发生在**创建/补建**与**语言页加载时的预填**：加载时若 `zh` 为空且 `en` 非空，中文输入框预填英文值并标记「英文回填」，保存后写入；
- 不调用翻译服务，英文值本身仍需用户填写或由 `displayName` 提供。

### 4.3 页面结构

```
语言
├── 顶部：文件路径（标准/回退）、统计（物品数 / 缺中文 / 缺英文 / 其他键）、保存按钮
├── 缺失提示：N 个物品缺少语言键 →「补建缺失键」（旧项目）
├── 筛选：全部 / 缺中文 / 缺英文 / 有修改 / 其他键；搜索框
├── 表格：键（只读 code） | 类型 | 显示名 | 中文（输入框） | 英文（输入框） | 状态
└── 底部：其他键（折叠，只读） | 说明文案
```

交互：

1. 行内编辑中文/英文，受控于本地 `draft`（`{ [key]: { zh, en } }`）；
2. 顶部「保存修改（N 处）」按钮，N 为改动键数；无改动时禁用；
3. 保存前调用 `lang.preview` 展示将写入的文件与新增/修改/删除的键数，确认后 `lang.save`；
4. 「仅显示缺失」开关；搜索按 id、显示名、键、值过滤；
5. 保存成功后重新加载列表；失败时保留草稿并显示错误；
6. 离开页面时若有未保存修改，使用 `beforeunload` 提示（与物品编辑器一致）；
7. 语言文件损坏时页面进入只读模式：显示警告、禁用输入与保存，提示先修复文件；
8. 「其他键」只读，不提供编辑或删除入口；
9. 空字符串 = 删除该键（决策 2）：清空输入并保存即删除，确认框列出删除数。

#### 4.4.2 `changes` 结构与合并规则

```json
{
  "zh_cn": { "item.examplemod.ruby": "红宝石", "item.examplemod.old": "" },
  "en_us": { "item.examplemod.ruby": "Ruby" }
}
```

- 基于当前文件内容合并：未提交的键原样保留；
- 值为空串 = 删除该键；值为非空 = 写入/覆盖；
- 只允许写 `entries` 中存在的键（`keyMissing` 的键由 `ensureItemLanguage` 补建，不接受 `changes` 直接创建）；
- `others` 的键拒绝写入；
- 写回时保持现有键顺序，新键追加到末尾；不排序，避免无关 diff。

### 4.5 API（`lib/api.js`）

| action | payload | 返回 | scope |
| --- | --- | --- | --- |
| `lang.list` | `{ path }` | `{ modid, standard, root, files, entries, others, stats, warning? }` | studio |
| `lang.preview` | `{ path, changes }` | `{ files: [{ locale, path, action, added, updated, removed }], changes }` | studio |
| `lang.save` | `{ path, changes }` | `{ files, backupDir, historyEntry }` | studio |
| `lang.ensure` | `{ path }` | `{ created: number, files, backupDir, historyEntry }` | studio |

- `lang.ensure` 只为 `keyMissing` 的物品补建键，不接受任意键；
- `lang.save` / `lang.ensure` 不刷新 `summary.json`（语言不影响摘要）；
- 生命周期写入（创建/删除/改名）由 `items.save` / `items.delete` 内部调用 `lib/lang.js`，不新增对外动作；
- 动作数：50 → 54。

### 4.6 写入事务

```text
1. 读取当前 zh_cn / en_us（损坏 → 拒绝保存）
2. 校验 changes 的键（只允许 entries 键；locale 只允许 zh_cn / en_us）
3. 合并出最终文件内容；无变化 → 返回 { files: [] }
4. 备份受影响文件：复用 content 备份目录与 manifest 格式
   （$DSH_HOME/mcmods-studio/backups/<项目>-<路径摘要>/<时间>-<随机>-content/）
5. 原子写入（writeJson）
6. 追加内容历史：scope 为 project（语言页保存）或 item（生命周期），见第 5 节
7. 资源写入失败 → 用备份恢复并抛错
8. 历史写入失败 → 用备份恢复并抛错（与 content.apply 一致）
```

备份格式与 `content.apply` 相同，因此旧 `content.rollback { backupDir }` 也能恢复语言文件。

### 4.7 边界

| 情况 | 处理 |
| --- | --- |
| 语言文件不存在 | 按空对象处理，保存/补建时创建 |
| 语言文件损坏 | `lang.list` 返回 `warning` 且只读；`lang.save` / `lang.ensure` 拒绝并提示先修复 |
| 其他模组/手写键 | 保留；归入「其他键」，只读 |
| 物品改名/删除后的旧键 | 保留并在「其他键」显示；本期不自动删除 |
| 未注册物品的键 | 不提供新增入口，只读 |
| 删除物品时语言文件不存在 | 跳过，不报错 |
| 删除/创建语言键失败 | 不阻塞物品保存/删除；返回 `warnings`，提示语言键未同步 |
| 并发写入 | 语言写入使用 `withHistoryLock` 串行化「读-合并-写-记历史」；与 `content.apply` 的交错写入仍是已知限制（同进程 UI 串行，风险低） |
| 空值语义 | 空串 = 删除该键；界面清空输入并保存即删除，确认框会列出删除数 |

### 4.8 验收

1. 「语言」页列出全部物品与方块，中文/英文值正确回填；
2. 缺失中文或英文的行有明确标记，可筛选；
3. 缺失中文时，中文输入框默认用英文值回填（标记「英文回填」）；
4. 修改一个值并保存：语言文件只改该键，其他键（含未知键）不变；
5. 清空一个值并保存：该键被删除，文件合法；
6. 新建物品后自动出现语言键（值为英文回填规则）；
7. 删除物品后对应语言键被移除；
8. 旧项目点「补建缺失键」后，缺失键被创建；
9. 保存前能看到将写入的文件与变更键数；
10. 保存后重新加载，语言页与物品编辑器回填一致；
11. 语言文件损坏时只读且给出提示，不覆盖文件；
12. 备份目录保留，历史中能看到语言步骤，可用旧 `content.rollback` 恢复。

## 5. `COMPAT-04` 历史记录适配

### 5.1 历史条目的范围

语言文件的所有写入都会追加到 `.mcstudio/content-history.json`：

| 场景 | entry.scope | itemId | title 示例 |
| --- | --- | --- | --- |
| 语言页保存 | `project` | `''` | `语言文件：zh_cn/en_us` |
| 补建缺失键 | `project` | `''` | `语言文件：补建缺失键` |
| 创建物品连带创建 | `item` | 新物品 id | `创建 ruby：语言` |
| 删除物品连带删除 | `item` | 被删物品 id | `删除 ruby：语言` |
| 改名迁移 | `item` | 新物品 id | `改名 ruby → ruby_sword：语言` |

- `content-history.json` 的 entry 新增可选字段 `scope: 'item' | 'project'`，缺省按 `item`（向后兼容，旧记录无需迁移）；
- `appendHistoryEntry` 接受 `scope`，写入时保留；`listHistoryEntries` 支持按 scope 过滤；
- 生命周期写入的 `files` 仍是语言文件（`kind: 'lang'`），回滚时恢复语言文件。

### 5.2 历史弹窗适配

- 默认「当前物品」筛选：只显示 `scope === 'item'` 且 `itemId` 匹配的步骤；项目级语言步骤不显示；
- 「全部」筛选：显示所有步骤，项目级步骤带「项目级」徽章；语言步骤标题明确；
- 被删除物品的历史仍保留（`itemId` 指向已删除 id），「当前物品」找不到该物品时不会展示，但在「全部」可见；
- 回滚：
  - 回滚项目级语言步骤：恢复语言文件；
  - 回滚物品级语言步骤：恢复语言文件；若物品已删除，恢复后该键会成为「其他键」，界面提示；
- 历史弹窗的「回到这一步」语义不变：保留目标步、撤销其后步骤；语言步骤与内容步骤共用同一条时间线。

### 5.3 测试

- `test/18-content.mjs` 或 `test/19-lang.mjs` 增加：
  1. 语言页保存后历史出现 `scope: project` 条目；
  2. 创建/删除物品后历史出现对应条目；
  3. 回滚语言步骤恢复语言文件；
  4. 旧历史文件（无 `scope`）读取时按 `item` 处理，不报错。
