# 小版本修复计划（fix）

> 用途：存放 PATCH 版本内的 bug 修复、交互优化、小功能增强与小范围内容改进计划。
> 规则：先写计划，作者确认后再改代码；计划中必须标明「是否采纳」「实现状态」「验收状态」。
> 最后更新：2026-10-31

## 适用范围

适合放进本目录的内容：

- 已发布功能中影响使用的 bug；
- 现有页面的交互/文案/性能优化；
- 不改变版本主线的局部增强；
- 需要先对齐语义、再动代码的回滚/历史类功能。

不适合：

- 新的大阶段能力（放 [../PLAN.md](../PLAN.md) 与 [../design/](../design/README.md)）；
- 跨模块重构（放 [../plans/](../plans/README.md) 对应模块计划）；
- 尚未决定是否做的想法（先建想法卡）。

## 文档命名

```text
docs/fix/V0.2.1-PLAN.md
docs/fix/V0.2.2-PLAN.md
```

一个 PATCH 版本一份计划；多个互不相关的小修复可以合并在同一份里，但每条必须有独立编号。

## 状态字段

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| 是否采纳 | `是` / `否` / `待确认` | 作者是否同意做 |
| 实现状态 | `未开始` / `进行中` / `已完成` / `已回退` | 代码是否已改 |
| 验收状态 | `待验收` / `通过` / `失败` | 是否按验收步骤验证过 |

> 「采纳」不等于「实现」。计划阶段只允许改文档，不允许顺手改代码。
