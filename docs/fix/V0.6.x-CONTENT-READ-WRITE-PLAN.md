## 3. 核心决策（施工默认约束）

### D01｜三类身份，禁止只以 ns:id 充当所有节点键

- 注册节点：`registry:<registryKey>|<namespace:path>`。
- 资源节点：`resource:<resourceKind>|<namespace:path>`，语言键还必须带 locale。
- Java 定义节点：`symbol:<项目相对路径>|<限定符号名>`，用于未注册的 Tier/材质/工厂等。
- UI 聚合条目：独立 presentationKey，可关联多个事实节点。

示例：`registry:minecraft:item|demo:machine` 与 `registry:minecraft:block|demo:machine` 是两个对象，以 blockItem 边相连；UI 可以是一张卡片。不同 ns 的同名对象也不能冲突。

注册 key 的实际名称由目标 loader/version 适配器确认；拼接键必须通过统一 encode/decode 函数，不允许各模块自行 split 猜结构。

### D02｜事实、推导、意图分离

1. observations：对文件/注册声明的观察，自动扫描维护。
2. resolved facts：通过受限规则得到的值，携带依赖与条件。
3. annotations/intents：人工描述、目标值、手工覆盖与待确认判断，不由扫描覆盖。

人工输入的目标值不改变“当前工程有效值”。只有提交后重新扫描匹配，才可标记 applied。

### D03｜来源和可信度正交

sourceKind 使用 java/json/version-rule/dependency/runtime-snapshot/manual；resolution 使用 resolved/partial/unknown/conflict；basis 使用 explicit/derived/default-rule。mtime 新并不代表语义准确。

Java/JSON 不天然 exact；字段确定性须取决于表达式解析、依赖闭合、覆写/条件和资源层级。运行时快照只代表该次环境与条件，不高于一切静态事实。

### D04｜默认值有前提，缺字段不等于默认值

只有确认构造/继承/Properties 调用链完整、无未解析覆写和影响因素时，才可据已验证的版本规则产生 default-rule 值。否则 unknown；`0`、`false`、空数组和 `null` 均可是真实值，不能用真假判断代表缺失。

### D05｜关系图为主数据，卡片不维护第二份事实

图边只存引用、角色和证据；卡片内 relations/resources 为查询投影，不持久复制另一份可编辑图。新扫描按来源替换对应自动边，不能只合并去重而永久保留已失效边。人工边独立保留，失去目标时标记 dangling。

### D06｜扫描是观察，不自动修改真实工程

扫描可写派生索引，但不生成缺失模型、补语言、删旧注册或修改 Java/资源。现有带副作用的导入行为必须拆开：发现结果、卡片同步、资源修复分别展示。项目清理不再由旧 API 静默删除。

### D07｜读取范围大于直接写回范围

每个字段有 editable capability；动态表达式可读不代表可写。共享定义不能默认修改；不确定目标转受控工程任务，而不是重新生成整文件覆盖。

### D08｜工程内容身份重命名不做首批直接编辑

修改 registry id、namespace、包名、类名可能影响代码、数据包和依赖引用。首批只预览影响并转任务；不得把旧卡片 `id` 改名等价成完成工程重命名。

### D09｜单进程锁，不假装跨进程事务

保留现有边界：所有插件入口同进程按规范化真实项目根串行；外部编辑器/其他 Host 用基线 hash 检测冲突，但不能宣称完全隔离。禁止保存旧确认凭据继续跨未知变化写盘。

### D10｜依赖与拆版决策门

本计划推荐 AST/CST 方向，但不指定未经验证的包。T40 提交候选许可证、Node/发行打包兼容、包体、语法覆盖、source span 与定位能力小样。若需新生产依赖或 native/JVM sidecar，先交作者确认，禁止静默引入。版本分批为发布候选，不自动 bump。

## 4. 目标数据契约

以下是拟议契约，不是当前 API。施工时保持语义不变；最终名称在 T10 冻结，并通过测试固定。

### 4.1 ContentNode

```json
{
  "key": "registry:minecraft:item|demo:ruby_sword",
  "identity": { "kind": "registry", "registry": "minecraft:item", "id": "demo:ruby_sword" },
  "implementation": { "className": "demo.item.RubySwordItem", "resolution": "resolved" },
  "categories": ["weapon", "sword"],
  "registration": { "resolution": "resolved", "evidenceIds": ["ev-register-1"] },
  "fieldIds": ["field-stack-1", "field-tier-1"],
  "lifecycle": "present"
}
```

分类是多标签；兼容旧 `type` 时生成主分类，但不能以主分类推断所有属性。生命周期可为 present/unresolved/stale/removed；removed 不等于删除人工资料。

### 4.2 FieldFact

```json
{
  "id": "field-stack-1",
  "ownerKey": "registry:minecraft:item|demo:ruby_sword",
  "field": "item.maxStackSize",
  "resolution": "resolved",
  "value": 1,
  "basis": "explicit",
  "evidenceIds": ["ev-stack-1"],
  "dependsOn": [],
  "conditions": [],
  "editCapability": "direct-literal"
}
```

约束：

- unknown/partial/conflict 可以记录候选或表达式，但不提供假定为真的 effective value；JSON 中用显式 resolution，不依赖 undefined。
- 非有限数拒绝；单位、范围、字段语义在 schema 中声明。
- 默认规则必须引用 ruleId/version；派生值必须列依赖。
- 多源不一致保留 alternatives 和 conflict，不静默按文件扫描顺序选最后一个。
- 手工 override 有作者/时间/理由及 old source 基线，但显示为 override，不伪装成 observed。

### 4.3 Evidence

```json
{
  "id": "ev-stack-1",
  "sourceKind": "java",
  "path": "src/main/java/demo/ModItems.java",
  "fileHash": "sha256:...",
  "span": { "start": 120, "end": 121, "offsetUnit": "utf16" },
  "symbol": "demo.ModItems.RUBY_SWORD",
  "expression": "1",
  "parserVersion": "content-java-v1",
  "ruleId": "forge-1.20.1-item-properties-stacksTo"
}
```

- span 为半开区间，JS 字符串 UTF-16 code unit；与 UTF-8 字节预算严格区分。
- 行列号只供展示，写入必须验证 hash+span+原文，不能按行号模糊替换。
- 外部依赖证据携带 artifact 坐标/版本/hash；runtime-snapshot 携带运行配置、采样时刻和条件。
- 如解析器不能提供可靠 span，字段必须 read-only，不拼猜位置。

### 4.4 ContentEdge

字段：`id/type/from/to/role/conditions/evidenceIds/resolution/sourceOwner`。

| 关系 | 方向与额外语义 |
| --- | --- |
| blockItem | item → block；允许不同 id，不能只按同名推断 |
| spawnEgg | item → entity type |
| tier / armorMaterial / foodDefinition | item → symbol/已知版本定义 |
| creativeTabMember | tab → item，保留顺序和条件，反向查询供物品详情展示 |
| tagMember | tag → item/block/tag；保留 required/optional 和直接/传递区别 |
| recipeIngredient / recipeResult | recipe → item/tag；保留 slot/count/候选，不用一条含糊 recipe 边代替 |
| lootReference / lootDrop | table → table/item/tag；block → table 是单独声明/规则关系 |
| modelParent / modelTexture / blockstateModel | 资源 → 资源；保留 variants、multipart 条件、权重 |
| displayName | 注册对象 → locale+语言键；使用实际 descriptionId 或已确认默认规则 |

边 ID 用规范化语义键产生稳定 hash；角色、条件不同的边不得错误去重。多跳派生边与原始声明边区分，不能把嵌套标签展开后失去原始结构。

### 4.5 ResourceRecord

字段至少包含 `key/type/location/origin/declaredRefs/resolution/contentHash/warnings`。

resolution：local/dependency/unresolved/missing/custom-renderer/conflict。

- missing 只在相应搜索范围完整、引用确定且目标找不到时使用；缺依赖或适配器不支持是 unresolved。
- 同名资源多 source set/数据包层级，保留候选和优先级；无法确认加载顺序不冒充最终有效资源。
- `src/generated/resources`、自定义资源源集与外部依赖纳入显式根配置；不得不受限地扫描整台磁盘。
- builtin 模型、parent 变量、纹理 alias、循环引用均需处理；循环产生诊断和深度界限。

### 4.6 ScanSnapshot

字段至少包含：schemaVersion、scanId、projectKey、target(loader/mc/mappings)、parser/rules版本、inputManifest、nodes、fields、edges、resources、diagnostics、coverage、createdAt。

coverage 细化到 domain/sourceRoot/file；complete/partial/unsupported/failed/cancelled，附 skipped/limitReached 原因。整体没有错误不等于所有注册完整。读到一半文件变化应重试或标记不一致快照，不能发布“完整”。

inputManifest 记录相对路径、内容 hash、存在性，及源根/规则配置。hash 可通过 mtime/size 缓存优化，但确认/提交与决定删除时必须使用内容 hash，不能只依赖时间戳。

拟议采用旁路索引，保留原卡片：

```text

  content-index/
    manifest.json                 # 当前 generation 与 schema/parser/target
    generations/<scanId>/...       # 可重建自动快照，分片格式由T10固定
  content-annotations.json         # 人工说明、覆盖、意图、旧值来源不明记录
  content-changes/                 # 确认凭据、提交日志、恢复信息
  items/*.json                    # 现有卡片保持兼容，不当作新事实权威来源
```

- 不新增含糊的单一 items.json 来代替当前每卡文件。
- generation 先写完整、校验、原子切 manifest；失败保留旧 generation 并标 stale，不混半新半旧。
- 人工事实文件损坏 fail-closed；派生索引损坏可重建，但必须显式提示，不顺带覆盖人工数据。
- schemaVersion 不支持时拒绝写；缺失文件和损坏文件区分。
- 默认保留当前和上一代索引；事务引用的 generation/备份不能由清理任务删除。GC 明确可重建/可回滚数据边界。

## 5. Java 识别与版本规则

### 5.1 识别流水线

源根发现 → 有界读文件 → 语法分析 → 符号/继承索引 → 注册候选 → 常量/受限调用求值 → 字段与关系提取 → 诊断 → 快照。

首批语法与求值支持：

1. import/static import、限定符、字段赋值、lambda、构造器调用、链式调用、嵌套泛型。
2. 字符串/数字/boolean/enum 常量、同项目静态 final 引用、括号与有限算术。
3. 确定性工厂包装：仅允许可分析返回式与显式形参替换；不执行方法。多返回、递归、循环/条件无法确定则 partial。
4. 有界解析自定义 Item 子类与构造器 super 链；方法覆写影响字段时降级，不能只识别类名后缀。
5. Tier/ArmorMaterial/FoodProperties 的静态 builder、简单 getter、常量表和可验证 switch 分支；其他形式保留符号与未知值。
6. 创造栏 builder 和事件 accept/add：记录多对多、顺序、条件；依赖权限/特性开关无法求值时保留条件。
7. 注册变量名不是类型判定依据；实体/音效/方块实体注册不能退回成 item。

### 5.2 资源上限

首版默认：单 Java 文件 1 MiB、单 JSON 4 MiB、源文件 20,000 个、解析总字节 128 MiB、符号递归深度 32、单次求值步数 10,000、总扫描 deadline 60 秒（不含依赖建立/构建）。所有限额可配置并设上界；触发上限返回 partial+诊断，禁止自动删除。

这些是安全初值，不是性能承诺；T80 根据 fixture 基准调整，变更须在交接记录中说明。JAR/ZIP 沿用受限解压策略并补总量/条目/压缩算法边界，不将全部依赖无选择展开到内存。

### 5.3 属性语义与来源优先级

不是全局“Java 永远胜过标签”，而是按字段处理：

| 字段组 | 必须解析/区分 | 未知策略 |
| --- | --- | --- |
| 堆叠/耐久 | 完整 Properties 调用顺序、构造/继承默认和覆写 | 不确定不赋 64/0/1；冲突调用交版本规则判定 |
| 分类 | 确定的继承关系主类别，标签提供附加类别；有冲突诊断 | 自定义类未解析保留候选，不按名字强行 weapon |
| 工具 | Tier 名称/身份、uses/speed/level/enchantment/repair ingredient | 名称已知数值未知分别记录 |
| 攻击 | 构造参数、属性 modifier 的 amount/operation/slot、Tier 派生、运行时最终值 | 不把构造器 dmg/speed 写成最终面板数值 |
| 护甲 | material+slot、耐久、defense、toughness、knockback、repair | 禁止固定槽位映射1/3/2/1 |
| 食物 | nutrition、saturationModifier、meat/alwaysEat/fast、effects与概率 | 区分饱和度系数和最终增加量；动态效果条件留空/partial |
| 其他 | rarity/fireResistance/craftRemainder/noRepair | absence 与 unknown 区分；依赖目标能反查 |
| 语言 | 实际 descriptionId、BlockItem规则、locale键 | 不全靠 item.ns.id 拼接；资源型候选不能证明注册 |

T00/T41 必须从目标版本依赖核验默认和公式，记录可复核规则依据。Forge 扩展和不同 mappings 名称经 adapter 处理。报告中燃料标签、enchantable 等不能直接视为 1.20.1 通用规则；没有版本证据就不启用。

## 6. 资源解析、导入与迁移

### 6.1 资源解析

- 模型：解析 parent、textures alias、layers、overrides、block model 引用；外部 builtin 不误报本地缺失。
- blockstate：variants/multipart 全收集；门/作物模型阶段仅为资源状态，不凭后缀创建或合并注册节点。独立注册的 wall/sign 或 stage 方块必须保留真实身份。
- 标签：区分 item/block registry、嵌套标签、replace/optional；未加载完整数据包栈时只声称声明成员，不声称游戏最终集合。
- 配方：先支持 1.20.1 已核验的常见 recipe serializer；保留 shaped 空格、slot、count、tag与item区别；未知 type 作为 opaque JSON 保存，不降为简单配方。
- 掉落：默认路径仅是版本规则候选，优先跟随明确声明；复杂条件/函数/嵌套表保留结构。不存在一律 block:table=1:1 的假设。
- 依赖：按当前项目版本/classpath查找，记录坐标和指纹。依赖未就绪则 unresolved，禁止扫描其他 MC 版本缓存来“补齐”。

### 6.2 统一预览与执行

导入、reimport、refresh、prune 使用同一 ScanSnapshot/ImportPlan：

1. 预览列新增、变化、冲突、未解析、失去证据、拟移除及理由；包含所有自动卡片变化。
2. proof 绑定项目真实根、schema/parser/rules、源根配置、完整相关输入 hash、旧索引 revision、人工资料 revision 和规范化 diff。
3. 执行前重核 proof；新增文件也会改变输入集合，不能只核已知文件。
4. 不完整扫描不产生破坏性移除；旧记录保留 stale/unverified。
5. 完整扫描后仍仅可将“由插件扫描管理且确认不再注册”的自动记录标 removed；保留人工说明和旧卡片引用。
6. 自动关系按该来源重建，人工关系不覆盖；已删除来源对应边标失效/移除，不无限累积。
7. 预览与执行的差异必须为空；任何新增删除动作都需要重新预览和批准。

### 6.3 旧数据迁移规则

迁移默认先提供 dry-run，不在 boot 时批量改真实项目。

| 旧内容 | 迁移规则 |
| --- | --- |
| description/notes/canvas/分组等 | 原样保留到展示/人工资料，不让扫描重置 |
| 旧 properties 无来源 | 标 legacy-unattributed，完整保留；不能因等于0/64判默认或手改 |
| 新扫描事实 | 写新事实层；与旧值不同则显示冲突/旧资料，不默默覆盖 |
| 已知旧扫描错误 | 纠正新事实，旧值留迁移记录，不能直接丢历史 |
| 同 id block/item | 分开事实键，UI可聚合；旧type=block不证明BlockItem存在 |
| 多 namespace | 全限定身份；旧裸id映射不唯一时需人工确认，禁止猜命名空间 |
| 资源变体/旧实体误当物品 | 给出依据明确的迁移候选；人工资料归档/重关联不删除 |

迁移提交前备份原 `.mcstudio`、记录 manifest/hash/version；事务失败恢复。重复运行幂等。迁移回滚不回滚后来无关的工程修改；若基线改变，拒绝覆盖并提供人工恢复路径。

旧 API 读接口保留；写接口不能绕过新安全链路。旧 item_save 保存资料仍可用，但不得被 UI 表述为已改工程。若旧接口实际会改资源，必须进入统一变更预览/确认，缺凭据返回明确错误与下一步，不悄悄按旧协议写入。

## 7. 安全修改与提交协议

### 7.1 能力级别

- direct-literal：单一、明确、项目内的 Java 字面量或已支持 JSON 叶子字段。
- shared-definition：常量、Tier、材质、共享模型/贴图；必须显示所有已知引用和覆盖完整性。
- assisted-task：可定位但不能安全局部写，生成路径受限的工程任务。
- read-only：依赖包、生成输出、动态表达式或不受支持格式。

用户对“当前物品耐久”的修改不能默认为改共享 Tier。方案中显式选择 shared 或 object-local；object-local 方案只有适配器能证明有效且可定位时生成，否则转任务。影响集合不完整时不允许默认提交 shared 修改。

### 7.2 ChangePlan 最小契约

```json
{
  "planId": "cp-...",
  "projectKey": "...",
  "baseScanId": "scan-...",
  "intent": { "targetKey": "registry:minecraft:item|demo:ruby", "field": "item.maxStackSize", "requestedValue": 16 },
  "scopeChoice": "object-local",
  "dependencies": [{ "path": "src/main/java/demo/ModItems.java", "hash": "sha256:..." }],
  "changes": [{ "path": "src/main/java/demo/ModItems.java", "action": "modify", "beforeHash": "sha256:...", "afterHash": "sha256:..." }],
  "impact": { "affectedKeys": [], "coverage": "complete" },
  "requiredChecks": ["parse", "rescan-match"],
  "payloadHash": "sha256:..."
}
```

完整内容和 diff 按需读取；list 不返回整文件。批准绑定项目、plan/payload hash、所有变更及依赖基线、影响范围、有效期与来源。agent 的批准行为不能伪称人类点击；保留 source=user/agent 与授权上下文，依届时宿主策略判断是否允许。写后 accept 独立，不能再次调用 confirm 代替。

### 7.3 提交步骤

1. **预检**：路径、资源 id、schema、值域、支持能力、完整影响范围、所有写前条件。
2. **锁内复核**：规范化真实项目根；重读变更目标及依赖 hash、存在性、源根清单；核确认凭据与过期状态。不得预览后重新独立渲染出另一套内容。
3. **准备**：写事务日志及 before-images，包含新建/修改/删除动作；存完整 after hash；保留原编码/BOM/换行/权限所需信息。只允许已支持的编码，拒绝误转码。
4. **提交**：用预览确定的 after 内容写临时文件后替换；每步记录进度。多文件不是OS级原子，明确日志可恢复边界。
5. **记录**：任务/历史/凭据消费记录纳入同一恢复协议。saveTask/历史写失败也恢复，不能只保护writeFile。
6. **验证**：重新解析/扫描目标，比较语义 postconditions；共享内容同时检查声明的影响集合；必要时编译。扫描写入成功但 postcondition 不匹配按验证失败处理。
7. **完成或恢复**：通过才发布新事实快照、标 applied/awaiting-accept；失败在 after hash 仍匹配时恢复before。外部文件已变化不能强覆盖恢复，返回 recoveryRequired、事务ID、备份位置及受影响路径。
8. **幂等**：requestId+payloadHash；相同键不同内容必须冲突。回滚后旧请求重放不得假报当前仍已应用。

崩溃恢复：下次打开项目先检查未完成事务；禁止再提交重叠写入，提供只读诊断/recover。记录状态 prepared/writing/recording/verifying/committed/rollingBack/recoveryRequired。不能仅靠进程内catch承诺崩溃安全。

### 7.4 路径与破坏性操作

- 统一校验读写/备份/恢复路径；禁止绝对路径、父级跳转、UNC/device、大小写绕过、危险分隔符和不合法 ResourceLocation。
- ResourceLocation 合法子路径通过安全映射实现，不为图省事一律禁止 `/`；旧卡片文件名的兼容限制单独处理。
- 未存在目标检查最近已存在祖先 realpath；已存在目录/文件链接按默认政策拒绝跨根。提交前再次检查，承认外部竞态的剩余边界，不宣称消除所有TOCTOU。
- 外部依赖只读；生成源默认只读，需修改其 generator/source 而不是下次会被覆盖的输出。
- 删除资源前查询引用，缺影响完整性不自动删。整文件删除、注册删除与id重命名首批转任务。
- 对语言/模型/配方保留未知字段、其他条目与结构；不接受“解析不了先清空再保存”。

- 未确认apply、codegen旁路、确认后文件/依赖/源根变化、同requestId不同payload、回滚后重放。

### 10.3 往返验证判定

## 12. 风险与失败处置

| 风险 | 处置 |
| --- | --- |
| AST依赖不支持Java17或打包环境 | T40小样先验证；降级只读候选，不悄悄回退宽泛regex误识别 |
| 自定义实现导致求值扩张成解释器 | 限语法/深度/步骤；unknown+定位+受限任务，不扩大运行权限 |
| 导入清理误删 | coverage门槛、preview/proof同源、保留人工记录、删除单独确认 |
| 共享依赖修改扩大影响 | 反向图+scopeChoice+影响完整性，默认阻止不完整shared修改 |
| JSON重建丢未知字段 | 叶子patch/opaque保留；语义比较与未知字段回归 |
| 构建耗时/网络不可用 | 构建作为独立验证状态，skip不等于pass；记录离线证据和待实机 |
| 多文件崩溃/恢复失败 | before-image+journal+startup recovery；不覆盖外部新修改 |
| 旧卡片值来源不明 | legacy-unattributed原样保存，新事实并列，需用户选择才覆盖人工层 |
| 源码与安装副本不同 | 验收分别记录源码SHA、打包SHA、安装路径/版本与当前GUI；安装需授权 |
| Agent过度扩展范围 | 按任务ID/文件所有权施工；每任务提交、证据与下一步，禁止顺手大重构 |
