# v0.4.5 计划：模块、阶段与任务（构想 → 计划）

> 日期：2026-11-08
> 版本：v0.4.5（MINOR）
> 状态：**方案已确认（2026-11-09），待实施**
> 关联：[PLAN.md](../PLAN.md) 第 0/1/4/6/8/9 节、[V0.4.4-PLAN.md](V0.4.4-PLAN.md)、[VERSION-PLAN.md](../VERSION-PLAN.md)
> 已确认：界面统一称「模块」；层级为 **模块 → 阶段 → 任务**；确认粒度 **每次任务确认一次**。

## 0. 摘要

按产品定位（用户是计划师、agent 是程序员、插件是翻译与记忆工具），v0.4.5 把「计划」从任务清单升级为 agent 的**承诺与路径**：

```text
构想（用户语言） → 模块（职责边界） → 阶段（实现顺序） → 任务（执行契约）
                                                          ↓
                                            预览变更 → 用户确认 → 写盘
```

- **agent 是插件的主要操作员**：构想、模块、阶段、任务都由 agent 通过工具创建/更新；用户只在 DSH 对话中交流；
- **构想页**：只读列表（agent 创建/更新）；
- **计划页**：模块 → 阶段 → 任务（只读），任务级「预览变更 / 确认 / 回滚」；
- **记忆**：计划导出简报 + handoff，供下一个 agent 接手；
- **代码生成**：不再以固定模板一键生成为主路径，agent 产出、任务级确认。
- **接口齐全**：agent 工具覆盖构想/模块/阶段/任务/导出/预览/确认全流程；UI 只保留必要按钮。

## 0.1 现状与差距

| 现状 | 差距 |
| --- | --- |
| 计划页 = 「系统」+「任务」，系统字段：职责/不变量/依赖/检查 | 界面叫「系统」，与用户心智中的「模块」不一致；没有「阶段」 |
| 构想页 = features 记录 + 导出 | 没有与 agent/任务的交接入口；`task.ideaId` 字段存在但 UI 无入口 |
| 任务有 `systemId`，无阶段 | 无法表达「模块内先做什么、后做什么」 |
| 任务状态有 doing/review/done，无「用户确认」 | 写盘后无法区分「agent 认为完成」与「用户已确认」 |
| 「生成」按钮 = 模板骨架 | 与「计划=规划、代码=agent」冲突 |
| 计划数据分散在 systems.json / tasks.json | 缺少可导出的「计划简报」 |

## 1. 对象模型

### 1.1 模块（Module，原系统）

- 界面文案统一为「模块」；数据字段沿用系统卡（`responsibility`、`nonGoals`、`invariants`、`entryPoints`、`resources`、`dependsOn`、`checks`、`status`）；
- 数据文件：新增 `.mcstudio/modules.json`，结构 `{ schemaVersion: 1, modules: [...] }`；
- 兼容：读取时若 `modules.json` 不存在，回退 `systems.json`（同一结构）；保存写 `modules.json`，并保留 `systems.json` 不删（一个版本周期后再评估清理）。

### 1.2 阶段（Stage，新增）

- 属于模块，表达实现顺序与里程碑；
- 数据文件：`.mcstudio/stages.json`，结构 `{ schemaVersion: 1, stages: [...] }`（**已确认：独立文件，不内嵌**）；
- 字段：`id`、`moduleId`、`name`、`goal`、`order`、`status`（planned/doing/done）、`acceptance`；
- 校验：`moduleId` 必须存在；`order` 为整数；模块删除时阶段一并处理（或提示）。

### 1.3 任务（Task，扩展）

- 现有字段保留；新增：
  - `moduleId`（新字段，与 `systemId` 同步；读取时 `moduleId ?? systemId`）；
  - `stageId`（可选，必须属于该模块）；
  - `confirmed`（布尔，用户确认后才为 true）；
- 校验：
  - 任务必须有模块（`systemId` 或 `moduleId`）；
  - 若给 `stageId`，阶段必须存在且属于该模块；
  - 保留 `allowedPaths` 至少一条的约束。

### 1.4 构想（Idea，沿用 features）

- 数据不动（`features.json`）；
- 增加与任务的关联入口：任务保存时 `ideaId` 可指向构想；
- 构想状态（idea/planned/done）可随关联任务完成回填（可选，P3）。

## 2. 数据与兼容

```text
<项目>/.mcstudio/
├── features.json   # 构想（不变）
├── modules.json    # 模块（新；回退 systems.json）
├── stages.json     # 阶段（新）
├── tasks.json      # 任务（新增 moduleId / stageId / confirmed）
├── systems.json    # 旧数据（保留，一个版本周期）
└── ...
```

兼容规则：

- 读：`modules.json` → 否则 `systems.json`；
- 写：统一写 `modules.json`；
- 任务读：`moduleId ?? systemId`；写：两者同步（旧调用方仍可只传 `systemId`）；
- 旧测试与旧项目不回归。

### 3.2 Agent 工具（`lib/tools.js`）

- `plan` 工具：`module.list / module.save / module.delete / stage.list / stage.save / stage.delete / task.confirm / task.unconfirm / plan.export`；

- **接口清单（必须齐全）**：构想 CRUD、模块 CRUD、阶段 CRUD、任务 CRUD + 确认、计划导出、变更预览/应用/回滚、上下文、检查。

## 4. UI

### 4.1 计划页

```text
计划（模块 N · 阶段 M · 任务 K）
[刷新] [导出计划]

模块「锁核心」  （职责、不变量、依赖）
```

- **只读视图**：模块/阶段/任务由 agent 创建与更新，UI 不提供新增/编辑表单；
- 模块可折叠；阶段显示顺序与状态；
- 任务卡只保留必要按钮：上下文、预览变更、确认、回滚；
- 「生成」→ 改为「预览变更」（调用 `task.codegen.preview`，展示 diff/越界/检查），确认后调用 `tasks.confirm`；
- 顶部保留「刷新」与「导出计划」。

### 4.2 构想页

- **只读列表**：agent 在 DSH 对话中创建/更新构想，UI 不提供编辑表单；
- 显示想法、状态、关联任务数（`task.ideaId`）；
- 状态轻量：想法 / 已规划 / 已实现，由 agent 随任务进展回填。

### 4.3 其他页面

- 任务详情（若有）显示所属模块/阶段与确认状态；
- 首页/摘要显示「模块/阶段/任务」计数。

## 5. 任务级确认流程

```text
agent 调用 task.codegen.preview / task.apply（或写文件）
  → 插件展示 diff、越界、检查结果
  → 用户点「确认」
  → tasks.confirm 置 confirmed=true，状态 → review/done
  → 回滚时 tasks.unconfirm + 恢复备份
```

- 默认**每个任务确认一次**（不要求每次 diff 确认）；
- `confirmed` 只表示「用户已确认变更」；确认后任务状态 → `review`，`done` 由用户/agent 在验收后标记；
- `task.verify` 通过不等于用户确认，两者分开记录；
- 未确认的任务在计划页显示「待确认」徽标。

## 9. 风险

| 风险 | 应对 |
| --- | --- |
| 数据双写（systems/modules） | 读回退、写单一文件，一个版本后清理旧文件 |
| 阶段与任务层级复杂 | 阶段可选，任务可直接挂模块；UI 折叠 |
| 确认状态与检查状态混淆 | 分开字段：`confirmed` vs `result.checks` |
| 旧调用方只传 `systemId` | 兼容读取与同步写入 |
| 计划导出与工作台数据重复 | 导出到 `docs/`，不写入 `.mcstudio` |

## 10. 已确认的决策（2026-11-09）

1. **阶段数据位置**：独立 `stages.json`，不内嵌到 `modules.json`。
2. **计划简报格式**：Markdown，写入 `docs/plan/`。
3. **确认语义**：`confirmed` 表示「用户已确认变更」；确认后任务状态 → `review`，`done` 由用户/agent 在验收后标记。
4. **`systems.*` 别名**：保留一个版本，之后评估移除。
5. **操作分配**：agent 是主要操作员；用户只通过 DSH 对话；插件 UI 只保留必要按钮；agent 接口齐全。
