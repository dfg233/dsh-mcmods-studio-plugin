# 项目计划书

> 项目：模组工坊（`dsh-mcmods-studio-plugin`）
> 当前适配：**仅 Minecraft 1.20.1**（Forge / NeoForge / Fabric）
> 版本：v0.1.0 已交付；v0.2 做 Agent 接入，v0.3 起扩展代码与图形化能力
> 更新日期：2026-10-23

## 0. 插件宗旨

> **模组工坊是一个「人机共用」的模组开发工作台。**
>
> 它把模组开发中**可结构化的部分**（想做什么、有哪些内容、每个内容的属性、素材在哪、代码该长什么样）
> 从散落的笔记、脑子和源码里抽出来，变成**一份人和 agent 都能直接读写的结构化事实**。
>
> - 对 **agent**：提供准确、紧凑、可校验的项目上下文，让它不必反复读文件、猜结构、试错，
>   把 token 花在创作上而不是探测上；
> - 对 **用户**：提供直观的项目关系、清晰的内容视图和低门槛的编辑方式，
>   让不熟 Java 的人也能把想法变成可运行的模组。
>
> **判断标准**：任何新功能，如果既没有让 agent 更准确地理解项目，也没有让用户更容易地表达意图，
> 就不应该做。

### 0.1 三条设计纲领

| 纲领 | 含义 | 反面 |
| --- | --- | --- |
| **事实只有一份** | 用户改、agent 改、代码生成读，都基于同一份 `.mcstudio/` 数据 | 界面存一套、代码里写一套、文档再抄一份 |
| **上下文优先于生成** | 先保证 agent 能准确理解项目，再谈替它生成什么 | 内置一堆模板，agent 却不知道项目里已有什么 |
| **给人看的给人看，给机器看的给机器** | 界面求直观，接口求紧凑；同一数据按用途给不同表示 | 界面和接口返回同一坨 JSON |

### 0.2 当前定位与差距

| 宗旨要求 | 现状 | 差距 |
| --- | --- | --- |
| agent 能直接使用 | 只有 HTTP 接口，agent 需自写脚本 | 缺原生工具 |
| 上下文紧凑 | `boot` 返回 7.4 KB，物品全量读取 | 缺聚合视图与紧凑表示 |
| 可校验 | 无校验能力 | agent 无法自检 |
| 用户直观看到关系 | 只有列表与画布 | 缺关系视图 |
| 低门槛编辑 | 弹窗逐项填写 | 缺批量与内联编辑 |

> 具体改进方案与优先级见 [plans/AGENT-PLAN.md](plans/AGENT-PLAN.md)。

## 1. 设计目的

围绕宗旨，本插件承担三件事：

1. **为 agent 提供上下文**——把项目结构、内容清单、字段定义、校验结果以工具与紧凑数据的形式提供，
   让 agent 不必读源码或逐文件解析就能准确操作项目；
2. **为用户提供直观平台**——用关系视图、内容视图与低门槛编辑，把模组内容变成看得见、改得动的东西；
3. **衔接设计与实现**——结构化数据可生成规范的 Java 注册代码与资源 JSON，生成物可读可改，
   重复生成不破坏手写代码。

一句话：**结构化的事实是核心，界面与工具是它的两个出口。**

## 2. 版本适配策略

**当前只适配 Minecraft 1.20.1**，其他版本在后续版本中逐步适配。

| 阶段 | 适配范围 | 说明 |
| --- | --- | --- |
| v0.1.0 – v0.4.0 | 仅 **1.20.1** | 所有功能、模板、文档都只针对 1.20.1 验证；不做多版本兼容层 |
| v1.0.0 | 1.20.1 + **1.21.1** | 引入版本适配层，第二个版本验证抽象是否成立 |
| v1.1.0 起 | 按需扩展 | 候选：1.19.2（Forge 整合包常用）、1.16.5（经典版本）、1.18.2 |

扩展顺序不预先承诺，按作者实际需求与社区使用情况调整。

**为多版本预留的设计**（v0.1.0 就要遵守，避免以后返工）：

- 项目元数据里的 `mcVersion` 是**项目字段**，不是全局常量；新建项目时默认 1.20.1；
- 物品字段、功能状态、加载器列表等定义集中在 `lib/project.js`，按版本拆分为可选能力表；
- 代码生成模板按「版本 + 加载器」二维组织（`lib/codegen/templates/<mcVersion>/<loader>/`）；
- 文档导出在页眉标注目标版本，跨版本复用同一套渲染逻辑；
- 数据文件带 `schemaVersion`，未来迁移有据可依。

## 3. 设计原则

| 原则 | 含义 |
| --- | --- |
| 数据与代码分离 | 设计数据存 `.mcstudio/`，生成物写入工程源码与资源目录，二者可独立演进 |
| 生成物可读可改 | 生成的 Java / JSON 是正常代码，不加密、不混淆，作者可以直接接手修改 |
| 重复生成不破坏手写 | 生成区块用注释标记包裹，再次生成只替换标记区间，手写代码不受影响 |
| 不锁定工程 | 所有文件都是标准 Forge / NeoForge / Fabric 工程结构，删掉插件也能继续开发 |
| 中文优先 | 界面与文档均为中文，代码标识符遵循 MC 社区惯例（英文） |
| 单版本优先 | 先把 1.20.1 做扎实，再谈多版本；不为未验证的版本写兼容分支 |

## 4. 版本计划

### v0.1.0 —— 设计与素材管理（已完成）

- 项目：新建、打开、扫描、导入、快照；
- 构想：增删改、状态与优先级；
- 物品：列表 / 画布双视图、19 个属性字段、搜索；
- 素材：PNG 上传校验、预览、模型 JSON 编辑、缺失统计；
- 文档：`FEATURES.md`、`ITEMS.md`、`ITEMS/<id>.md`、`ASSETS.md`、`README.md`；
- 构建教程：1.20.1 三种加载器的 IDEA 流程；
- 界面：左侧图标区入口、右侧栏项目概览与物品详情。

### v0.2.0 —— Agent 接入（下一步优先）

依据宗旨「上下文优先于生成」，先解决 agent 能用、易用的问题，详见 [plans/AGENT-PLAN.md](plans/AGENT-PLAN.md)。

- **原生工具**：把项目摘要、条目读写、schema 查询、校验、文档导出注册为工具，
  agent 不必自写 HTTP 脚本；
- **`summary.json` 聚合**：一次读取掌握项目全貌，替代逐文件解析；
- **紧凑 / 详细双表示**：列举用紧凑格式，确认后取详情；
- **schema 外置**：字段定义抽成数据文件，agent 与工具共用同一份；
- **校验器**：id、数值范围、贴图缺失、模型引用、语言键缺失，输出分级问题与修复建议。

**验收标准**

- agent 不使用任何 `fetch` 代码，仅靠工具完成「读项目 → 改一条内容 → 导出文档」；
- 列举 12 个物品的返回体积从约 5000 字节降到 300 字节以内；
- 校验器能报出至少 6 类常见问题。

### v0.3.0 —— 代码工作区与代码生成

代码生成以**工具形式**提供，界面与 agent 共用同一实现（见 [plans/AGENT-PLAN.md](plans/AGENT-PLAN.md) 第 5.1 节路线 C）。

**代码工作区**

- 工程文件树：只展示允许编辑的文本文件（`.java`、`.json`、`.toml`、`.gradle`、`.properties`、`.mcmeta`、`.md`）；
- 编辑器：行号、等宽字体、Tab 缩进、未保存提示、`Ctrl+S` 保存；
- 安全约束：路径必须位于工程内（拒绝 `..` 穿越）、单文件 ≤ 1MB、只允许文本扩展名；
- 冲突处理：保存前比对修改时间，文件被外部改动时提示覆盖或放弃。

**代码生成**

- 物品注册：按物品列表生成 `ModItems.java`（`DeferredRegister` / `Registry.register`，按加载器切换模板）；
- 创造模式标签：按物品的 `creativeTab` 字段生成标签注册；
- 资源 JSON：物品模型、`blockstates`（方块）、`lang/zh_cn.json`、`lang/en_us.json`；
- 生成区块标记：
  ```java
  // <mcstudio:generated items>
  public static final RegistryObject<Item> RUBY = ITEMS.register("ruby", ...);
  // </mcstudio:generated>
  ```
  再次生成只替换标记区间，标记外的手写代码原样保留；
- 生成前预览：列出将新增 / 修改 / 跳过的文件，由作者确认后写入。

**验收标准**

- 能在插件内打开并保存工程中的 `.java` 文件，保存后 IDEA 可直接编译；
- 生成物品注册代码后，`gradlew build` 通过（在示例工程上验证）；
- 重复生成两次，手写代码与标记外内容零差异。

### v0.4.0 —— 图形化内容创建

- 方块：属性表单（硬度、抗性、掉落、光照、音效）、方块模型与 blockstate 生成；
- 配方：工作台有序 / 无序、熔炉、切石机，图形化摆放格子并导出 JSON；
- 创造模式标签：拖拽排序物品；
- 语言文件：由显示名自动生成中英文条目；
- 战利品表：方块掉落配置；
- 图形化与代码联动：新建方块后自动生成注册代码与资源文件。

**验收标准**

- 新建一个方块并填写表单后，工程中自动出现注册代码、blockstate、模型、lang 条目；
- 配方面板能导出被游戏正确加载的 JSON。

### v0.5.0 —— 质量与效率

- 素材引用检查：模型引用不存在的贴图、物品缺模型、lang 缺键；
- 快照差异对比：重新导入工程时列出新增 / 变更 / 删除；
- 批量贴图导入：多选或整目录导入并按 ID 匹配；
- 物品复制与批量编辑；
- 关系视图：依赖图、缺失面板、变更时间线（见 [plans/AGENT-PLAN.md](plans/AGENT-PLAN.md) 建议 7）；
- 右侧栏标签自动打开（点左侧图标联动）。

### v1.0.0 —— 稳定版与第二个 MC 版本

- 引入版本适配层，新增 **Minecraft 1.21.1** 支持（第二个版本用于验证抽象）；
- 导入 `.jar` 解析；
- 完整回归测试与文档定稿。

### v1.1.0 起 —— 按需扩展版本

- 候选版本：1.19.2、1.16.5、1.18.2，按实际需求排序；
- 每个新版本需要：字段能力表、代码模板、构建教程、示例工程回归。

## 5. 非目标

- **不做完整 IDE**：不实现编译、运行、调试、反编译，这些交给 IDEA；
- 不做云端同步与多人协作；
- 不修改用户的构建脚本逻辑（只读取；生成代码写入独立文件或标记区块）；
- 不内置 MC 客户端或服务端；
- v0.5.0 之前不做多版本兼容（只保证 1.20.1）。

## 6. 技术路线

| 层 | 方案 |
| --- | --- |
| 工具层 | `lib/tools.js`：把项目摘要、条目读写、schema、校验、导出注册为 agent 可调用的工具，内部复用现有业务函数 |
| 聚合层 | `lib/summary.js`：维护 `<项目>/.mcstudio/summary.json`，写操作后增量刷新 |
| 数据层 | `data/schema.json`：字段定义外置，`lib/project.js` 读取它 |
| 校验层 | `lib/validate.js`：id、数值、素材引用、语言键、类型一致性 |
| Host | `lib/files.js`（文件树、读写、白名单、大小限制）、`lib/codegen.js`（模板与标记区块替换）；沿用现有 `webServer` 路由 |
| Client | 新增「代码」页：左侧文件树 + 右侧编辑器；沿用现有 `S`/`C` 样式与主题变量 |
| 数据 | `project.json` 增加 `codegen` 段：源码根目录、包名、主类名、加载器模板选择；`mcVersion` 存项目级字段 |
| 模板 | 按「版本 + 加载器」组织：`lib/codegen/templates/<mcVersion>/<loader>/`，先只有 `1.20.1/` |
| 版本能力表 | `lib/versions.js` 描述每个 MC 版本支持的字段、加载器与模板目录；先只登记 1.20.1 |
| 安全 | 所有路径 `assertInside(projectPath, target)`；写文件前做扩展名与大小校验 |

## 7. 风险与约束

| 风险 | 应对 |
| --- | --- |
| 生成的代码与作者手写冲突 | 标记区块 + 生成前预览 + 不覆盖标记外内容 |
| 不同加载器 API 差异 | 模板分加载器维护，生成前展示目标加载器 |
| 大工程文件树卡顿 | 懒加载目录，忽略 `build/`、`.gradle/`、`.git/` |
| 编辑器性能 | 单文件 1MB 上限，超出提示用外部编辑器打开 |
| 误改工程配置 | 允许编辑但默认只读打开 `build.gradle`、`gradle.properties`，需二次确认才可保存 |
| 多版本字段差异 | 版本能力表 + 项目级 `mcVersion`，不为未验证版本写分支 |
| 工具与 HTTP 动作重复实现 | 二者共用 `lib/` 业务函数，工具层只做参数适配 |
| `summary.json` 与真实数据不一致 | 视为派生数据，可随时由源数据重建；每次写操作后立即刷新 |
