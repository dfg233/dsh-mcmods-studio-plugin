# 项目计划书

> 项目：模组工坊（`dsh-mcmods-studio-plugin`）
> 当前版本：v0.1.0（已交付并运行）
> 当前适配：**仅 Minecraft 1.20.1**（Forge / NeoForge / Fabric）
> 更新日期：2026-10-25
> 本文档描述**方向与路线**。实现细节见 [STATUS.md](STATUS.md)，代码索引见 [INDEX.md](INDEX.md)。

## 0. 插件宗旨

> **模组工坊是一个「人机共用」的模组开发工作台。**
>
> 它把模组开发中**可结构化的部分**（想做什么、有哪些内容、每个内容的属性、素材在哪、
> 代码该长什么样）从散落的笔记与源码里抽出来，变成**一份人和 agent 都能直接读写的结构化事实**。
>
> - 对 **agent**：提供准确、紧凑、可校验的项目上下文，让 token 花在创作上而不是探测上；
> - 对 **用户**：提供直观的项目关系、清晰的内容视图与低门槛的编辑方式。

**判断标准**：任何新功能，如果既没有让 agent 更准确地理解项目，也没有让用户更容易地
表达意图，就不应该做。

### 0.1 三条设计纲领

| 纲领 | 含义 | 反面 |
| --- | --- | --- |
| **事实只有一份** | 用户改、agent 改、代码生成读，都基于同一份 `.mcstudio/` 数据 | 界面存一套、代码写一套、文档再抄一份 |
| **上下文优先于生成** | 先保证 agent 能准确理解项目，再谈替它生成什么 | 内置一堆模板，agent 却不知道项目里已有什么 |
| **给人看的给人看，给机器看的给机器** | 界面求直观，接口求紧凑；同一数据按用途给不同表示 | 界面和接口返回同一坨 JSON |

### 0.2 当前达成情况

| 宗旨要求 | 现状 | 落地方式 |
| --- | --- | --- |
| agent 能直接使用 | **已达成** | 17 个 DSH 原生工具（`mcmods_*`）+ 33 个 HTTP 动作 |
| 上下文紧凑 | **已达成** | `summary.json`（12 物品约 1.2 KB）、`item_list` 紧凑格式 |
| 可校验 | **已达成** | 9 类校验，分级 error / warning |
| 字段知识可读 | **已达成** | `data/schema.json` 对外副本 |
| 用户直观看到关系 | **未达成** | 只有列表与画布，缺依赖图与时间线 |
| 低门槛编辑 | **部分** | 有表单与弹窗，缺内联编辑与批量操作 |

## 1. 设计目的

围绕宗旨，插件承担三件事：

1. **为 agent 提供上下文**——项目摘要、条目读写、schema、校验，以工具与紧凑数据提供；
2. **为用户提供直观平台**——构想、物品、素材、文档集中在一处，可视化浏览与编辑；
3. **衔接设计与实现**——结构化数据可生成规范的 Java 注册代码与资源 JSON，
   生成物可读可改，重复生成不破坏手写代码。

一句话：**结构化的事实是核心，界面与工具是它的两个出口。**

## 2. 版本适配策略

**当前只适配 Minecraft 1.20.1**，其他版本在后续版本中逐步适配。

| 阶段 | 适配范围 | 说明 |
| --- | --- | --- |
| v0.1.0 – v0.5.0 | 仅 **1.20.1** | 所有功能、模板、文档都只针对 1.20.1 验证 |
| v1.0.0 | 1.20.1 + **1.21.1** | 引入版本适配层，第二个版本验证抽象是否成立 |
| v1.1.0 起 | 按需扩展 | 候选：1.19.2、1.16.5、1.18.2 |

**为多版本预留的设计**：

- 项目元数据里的 `mcVersion` 是**项目字段**，不是全局常量；
- 字段定义集中在 `lib/schema.js`，可按版本拆成能力表；
- 代码生成模板按「版本 + 加载器」二维组织（`lib/codegen/templates/<mcVersion>/<loader>/`）；
- 数据文件带 `schemaVersion`，未来迁移有据可依。

## 3. 设计原则

| 原则 | 含义 |
| --- | --- |
| 数据与代码分离 | 设计数据存 `.mcstudio/`，生成物写入工程源码与资源目录 |
| 生成物可读可改 | 生成的 Java / JSON 是正常代码，不加密、不混淆 |
| 重复生成不破坏手写 | 生成区块用注释标记包裹，只替换标记区间 |
| 不锁定工程 | 标准 Forge / NeoForge / Fabric 结构，删掉插件也能继续开发 |
| 中文优先 | 界面与文档均为中文，代码标识符遵循 MC 社区惯例 |
| 单版本优先 | 先把 1.20.1 做扎实，再谈多版本 |

## 4. 版本路线

### v0.1.0 —— 设计工作台（已完成）

- **项目**：新建、打开、扫描、导入、重新导入、详情、工坊标记；上次打开的项目持久化到注册表，重进插件自动恢复；
- **构想**：增删改、状态四档、优先级三档；
- **物品**：19 项属性五组、列表 / 画布双视图、搜索、拖拽持久化；
- **素材**：PNG 校验、上传、预览、模型 JSON 编辑、缺失统计；方块贴图按 blockstate → 模型 → parent 链 → textures 解析，按面展示（六面同图只显示一张）；
- **文档**：`FEATURES.md`、`ITEMS.md`、`ITEMS/<id>.md`、`ASSETS.md`、`README.md`；
- **构建教程**：内置 1.20.1 三种加载器的 IDEA 流程；
- **界面**：左侧图标区、主面板五页签、右侧栏项目概览；
- **Agent**：17 个原生工具、项目摘要、9 类校验、导入判定提示。

### v0.2.0 —— 关系视图与编辑效率（下一阶段）

按宗旨第 2 条，补齐「用户看不到关系」与「编辑成本高」两块。

| 事项 | 说明 |
| --- | --- |
| 依赖图 | 构想 → 物品 → 贴图/模型，复用画布的拖拽与排布 |
| 缺失面板 | 一屏列出所有缺贴图、缺模型、引用错误 |
| 变更时间线 | 按 `updatedAt` 倒序展示最近改动 |
| 内联编辑 | 列表内直接改名称、类型、堆叠，不必开弹窗 |
| 批量操作 | 多选后统一改类型或标签 |
| 撤销 | 编辑历史栈 |

**验收标准**

- 从某个构想能一键看到它关联的物品（需先在构想上增加 `itemRefs` 字段）；
- 缺素材的物品在一个页面内全部可见，并可点击跳转；
- 列表内改一个字段不需要打开弹窗。

### v0.3.0 —— 代码工作区与生成

代码生成以**工具形式**暴露，界面按钮与 agent 调用共用同一实现。

**代码工作区**

- 工程文件树：只展示白名单内的文本文件；忽略 `build/`、`.gradle/`、`.git/`；
- 编辑器：行号、等宽、未保存提示、`Ctrl+S`；
- 安全：路径限定工程内、单文件 ≤ 1MB、保存前比对 mtime；
- 冲突：文件被外部改动时提示覆盖或放弃。

**代码生成**

- 物品注册：生成 `ModItems.java`（`DeferredRegister` / `Registry.register`，按加载器切模板）；
- 创造模式标签、资源 JSON、`blockstates`、`lang/zh_cn.json`；
- 生成区块用注释标记包裹，重复生成只替换标记区间；
- 生成前预览：列出将新增 / 修改 / 跳过的文件。

**验收标准**

- 生成后 `gradlew build` 通过（在示例工程上验证）；
- 重复生成两次，手写代码与标记外内容零差异。

### v0.4.0 —— 图形化内容创建

- 方块：属性表单 + 方块模型 + blockstate 生成；
- 配方：工作台有序 / 无序、熔炉、切石机；
- 创造模式标签拖拽排序；
- 语言文件由显示名自动生成；
- 战利品表配置。

### v0.5.0 —— 质量与效率

- 素材引用检查深化（模型引用链、lang 缺键统计）；
- 快照差异对比：重新导入时列出新增 / 变更 / 删除；
- 批量贴图导入：拖拽整目录，按文件名匹配；
- 性能基线：100 物品规模下 `boot` 与 `summary` 耗时。

### v1.0.0 —— 稳定版与第二个 MC 版本

- 版本适配层，新增 **Minecraft 1.21.1**；
- 导入 `.jar` 解析；
- 完整回归测试与文档定稿。

## 5. 非目标

- **不做完整 IDE**：不实现编译、运行、调试、反编译；
- 不做云端同步与多人协作；
- 不修改用户的构建脚本逻辑（只读取；生成代码写入独立文件或标记区块）；
- 不内置 MC 客户端或服务端；
- v0.5.0 之前不做多版本兼容。

## 6. 技术路线

当前实现（v0.1.0）的分层：

| 层 | 模块 | 职责 |
| --- | --- | --- |
| 入口 | `index.js` | HTTP 路由、原生工具注册、卸载清理 |
| 分派 | `lib/api.js` | 33 个动作的声明式路由表 |
| 路径 | `lib/paths.js` | `.mcstudio/` 路径、id 校验、路径归属 |
| 定义 | `lib/schema.js` | 加载器、状态、类型、19 个字段 |
| 元数据 | `lib/meta.js` | `project.json` 与 `studio.json` |
| 条目 | `lib/entries.js` | 构想与物品 CRUD、`readProject` |
| 导入 | `lib/import.js` | 识别、扫描、差异、同步、快照 |
| 解析 | `lib/gradle.js` | `gradle.properties` 与占位符 |
| 素材 | `lib/assets.js` | PNG 校验、贴图与模型 |
| 导出 | `lib/docs.js` | 五份 Markdown |
| 摘要 | `lib/summary.js` | `summary.json` |
| 校验 | `lib/validate.js` | 9 类检查 |
| 工具 | `lib/tools.js` + `lib/tool-bridge.js` | 17 个工具定义与 DSH 注册 |
| 兼容 | `lib/project.js` | 转发层，保持既有 import 路径 |

## 7. 风险与约束

| 风险 | 应对 |
| --- | --- |
| 生成的代码与手写冲突 | 标记区块 + 生成前预览 + 不覆盖标记外内容 |
| 不同加载器 API 差异 | 模板分加载器维护，生成前展示目标加载器 |
| 大工程文件树卡顿 | 懒加载目录，忽略构建产物 |
| 编辑器性能 | 单文件 1MB 上限 |
| 误改工程配置 | `build.gradle` 等默认只读打开 |
| 多版本字段差异 | 版本能力表 + 项目级 `mcVersion` |
| 工具与 HTTP 重复实现 | 工具直接复用业务函数，不重写逻辑 |
| `summary.json` 与真实数据不一致 | 视为派生数据，可随时重建；写操作后立即刷新 |
| 渲染层无自动化保护 | 已建 `test/12-render.mjs`，但不能验证样式与交互 |
