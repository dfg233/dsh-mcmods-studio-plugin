## 1. 设计

### 1.1 Client 请求代次（Q09）

- `boot`/`project.open`/`assets.list` 请求带代次（递增序号）；仅最新代次可写入状态；
- 项目与素材在同一代次内提交（先取项目，再取素材，失败则丢弃两者）；
- 切换项目时清空旧操作目标（素材编辑、模型编辑）。

### 1.2 素材缓存 revision（Q10）

- `assets.list` 返回 `revision`：素材文件集合的 mtime/size 汇总 hash；
- 前端图片与预览 effect 依赖 `revision`（不再依赖数量）；
- 替换同 ID 贴图、只改 layer、只改模型 → revision 变化 → 重新读取。

### 1.3 上下文预算（Q11）

- `context.pack` 使用 UTF-8 字节数（`Buffer.byteLength`）；
- 裁剪顺序：先截长文本（acceptance/notes），再截列表，最后保留最小元数据；
- 最终结果必须 ≤ 预算；不可裁的超限返回明确错误与「已裁剪」说明；
- 预算参数上界（如 1–256KB）。

### 1.4 API 索引（Q12）

- 静态回退只扫描项目 `gradle.properties` 声明的 MC/Forge 版本；
- 索引记录 `source`（gradle/classpath/static）与 `confidence`；多版本缓存冲突时标注；
- 缓存键加入 JAR 指纹（路径 + size + mtime），同路径替换可识别 stale。

### 1.5 增量扫描（Q13）

- `structure.refresh`：先读文件并计算 hash，未变文件直接复用（不调用 `parseJava`）；
- 删除检测用「旧集合 - 新集合」；
- 测试断言第二次刷新 `parseJava` 调用次数为 0。

### 1.6 门禁与文档（Q14/Q15）

- `package.json scripts`：`lint:syntax`（对入口 `node --check`）、`test`、`gen:schema`、`check:docs`（数字校验）；
- `engines.node >= 20`；
- 文档数字（动作/工具/模板/测试）由脚本校验，发版流程引用。
