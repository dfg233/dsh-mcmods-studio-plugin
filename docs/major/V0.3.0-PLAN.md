# v0.3.0（M2）实现方案：API 索引、模板、上下文包与检查

> 版本：v0.3.0（MINOR）
> 状态：**已实现、已验收**（2026-11-04；验收记录见第 16 节）
> 关联：[PLAN.md](../PLAN.md) 第 9 节 M2、[design/API-INDEX-SPEC.md](../design/API-INDEX-SPEC.md)、[design/TEMPLATE-SPEC.md](../design/TEMPLATE-SPEC.md)、[design/TASK-SPEC.md](../design/TASK-SPEC.md)、[VERSION-PLAN.md](../VERSION-PLAN.md)、[STATUS.md](../STATUS.md)、[INDEX.md](../INDEX.md)

## 0. 摘要

M2 把插件从「内容编辑器」推进到「AI 工程工作台」：让 AI 知道项目依赖里**真实存在哪些 API**，按**模板**生成骨架，拿到**最小任务上下文**，并在写入后由**检查器**判定是否越界、是否缺资源、是否能编译。

四块能力按依赖顺序实现：

```text
API 索引（签名事实）
  → 模板（正确用法 + 文件骨架）
    → 上下文包（把任务需要的签名/代码/资源裁到预算内）
      → 检查器（越界、资源配对、结构差异、编译）
        → 任务执行（开始 / 应用 / 验证 / 回滚）
```

本文只写实现方案，不含代码。确认后按第 15 节顺序进入实现。

## 2. 目标与非目标

**目标**

- 从项目真实依赖提取类/方法/字段签名，支持 protected、继承、嵌套类；
- 提供可版本化、可 golden 测试的模板，渲染前预览、写入前备份、写入后检查；
- 为任务生成不超过预算的上下文包（文件数、字节数、API 类数）；
- 实现任务级检查：`allowed-paths`、`guard-paths`、`structure-diff`、`resource-exists`、`registration-pair`、`lang-key`，可选 `compile-java`；
- 任务可开始、应用、验证、回滚，状态机与证据可追溯。

**非目标**

- 不做完整 IDE：不编译整个工程、不运行游戏、不做反编译；
- 不做任意 Java 代码生成（模板只出骨架，业务逻辑由 AI 填充）；
- 不做代码工作区的自由编辑（v0.4）；
- 不做多 MC 版本；v0.3 仍只支持 1.20.1；
- 不把整个索引塞进提示词，也不默认执行项目构建脚本。

## 3. 总体设计

### 3.1 模块划分

| 新模块 | 职责 |
| --- | --- |
| `lib/api-index.js` | classpath 发现、javap 解析、缓存、查询（status/refresh/search/get） |
| `lib/templates.js` | 模板清单读取、参数校验、渲染、合并、预览、应用 |
| `lib/context.js` | 任务上下文打包与预算裁剪（依赖 api-index、structure、workbench） |

| `lib/tasks.js` | 任务执行编排：start / apply / verify / rollback（依赖 templates、checks、structure） |

数据流：

```text

任务/系统/模板 ──────────────┘                    │
                                                  ▼
模板渲染 + AI 变更集 ──> tasks.apply ──> 备份 ──> 写入 ──> checks ──> 结果/回滚
```

## 4. Phase A：API 索引

### 4.1 数据来源与模式

`api.refresh { mode: 'auto' | 'gradle' | 'static' }`，默认 `auto`：

1. **Gradle 精确模式**：生成临时 init 脚本，执行
   `gradlew -I <script> mcmodsDumpClasspath --offline`，读取输出的 `compileClasspath`；
2. **静态回退**：解析构建文件识别 loader/MC 版本，在 Gradle 缓存中按模块坐标定位 jar（`~/.gradle/caches/modules-2/files-2.1/`、ForgeGradle userdev 缓存、Fabric Loom 缓存）；
3. 两者都失败 → 返回 `{ available: false, reason }`，不阻塞内容编辑。

约束：

- 不修改 `build.gradle`、不写项目文件；
- 精确模式需用户明确开启（首次 `api.refresh` 时确认，或项目详情里的开关）；
- 所有 Gradle 调用 `--offline`、超时 180s、输出摘要化；
- 不执行项目代码。

### 4.2 提取与解析

```text
读构建文件 → 识别 loader / mcVersion / mappings / javaVersion
  → 获取 classpath（gradle 或 static）
  → 列 jar → 过滤包 → 批量 javap -p -s
  → 解析签名 → 分片写入缓存
```

- **优先 `javap`**（JDK 自带）：`javap -p -s -classpath <cp> <fqcn...>`，每批 100 个类，避免命令行过长；
- **无 JDK**：回退到「jar 内 `.class` 路径清单」，只提供类名与包，方法签名标记 `unknown`；
- 过滤白名单：`net.minecraft`、`net.minecraftforge`、`net.neoforged`、`net.fabricmc`、`com.mojang.blaze3d`、`com.mojang.math`；
- 排除：`*.impl.*`、`*.internal.*`、`*.mixin.*`、`*.datagen.*`；
- 记录：类名、kind、修饰符、父类/接口、方法（名、参数、返回、static、visibility、generic、deprecated）、字段（public/protected）、嵌套类；
- **继承**：索引只存本类声明；查询时沿父类链合并 public/protected 方法，标 `inheritedFrom`，不预合并全量（内存）；
- 嵌套类保留 `Outer$Inner` 与 `Outer.Inner` 两个键。

### 4.3 缓存与失效

```text
cache/api/<projectHash>-<classpathHash>/
  meta.json          # loader/mcVersion/mappings/javaVersion/source/stats/generatedAt
  classes/<package>.json
```

- `classpathHash` = jar 路径、大小、mtime、构建文件摘要的 sha256；
- 构建文件或依赖变化 → 新目录，旧目录不主动删除（可清理）；
- `api.status` 返回 `available`、`stale`（hash 不匹配）、统计与 `source`。

### 4.4 查询

| 动作 | 行为 |
| --- | --- |
| `api.status` | 是否存在、是否过期、统计、来源、失败原因 |
| `api.refresh` | 重建；返回摘要与耗时 |
| `api.search {query, package?, kind?, limit?}` | 类名/方法名/包名匹配，最多 50 条，只回摘要 |
| `api.get {class}` | 单类签名；`includeInherited` 默认 true |
| `api.context {taskId, budget?}` | 供上下文包取 `apiRefs`（最多 20 类 / 4KB） |

- 找不到时返回 `{ found: false, suggestions: [...] }`，不猜；
- 查询结果不缓存（索引已缓存），每次从分片读取。

### 4.5 降级与错误

| 情况 | 行为 |
| --- | --- |
| 无 JDK | `available: false, reason: "jdk-missing"`；类名清单仍可用 |
| Gradle 失败/超时 | 回退静态；仍失败则记录 `reason` |
| 构建文件无法解析 | 返回 `reason: "build-parse"`，提示手工指定 classpath |
| 索引过期 | `status.stale: true`，`api.context` 仍可用但标记 `stale` |

### 4.6 测试

- 固定 `javap` 输出 fixture（Item、BlockEntity、MenuProvider、嵌套类）→ 解析结果快照；
- 继承合并：父类方法出现在子类，`inheritedFrom` 正确；
- 过滤：`impl/internal/mixin` 不出现；
- 缓存：hash 变化生成新目录、`stale` 正确；
- 降级：无 JDK、Gradle 失败、构建文件缺失；
- 真实工程：Lock（Forge）索引到核心类，`BlockEntity.saveAdditional`、`MenuProvider.createMenu` 可查。

## 5. Phase B：模板

### 5.1 模板清单与存放

- 内置模板：插件根 `templates/<id>/`（`template.json` + `files/*.tpl` + `README.md`）；
- `package.json` 的 `files` 增加 `"templates/**"`；
- v0.3 先不做项目自定义模板（避免与内置版本冲突），留扩展点：`<项目>/.mcstudio/templates/` 优先级高于内置（后续版本）。

第一批模板（v0.3.0）：

| 模板 | 输出 |
| --- | --- |
| `simple-item` | 物品类 + 注册行 + 模型 + 语言 |
| `tool-set` | 工具类（耐久/攻击/采集）+ 注册 + 模型 + 语言 |
| `block-basic` | 方块类 + 方块物品 + blockstate + 模型 + 语言 |
| `shaped-recipe` | 有序配方 JSON |
| `shapeless-recipe` | 无序配方 JSON |
| `furnace-recipe` | 熔炉配方 JSON |
| `item-tag` / `block-tag` | 标签 JSON |
| `lang-pair` | 中英文语言条目 |

第二、三批（`block-entity-menu`、`uuid-key-item`、`s2c-sync-packet` 等）留给 v0.4。

### 5.2 渲染

- 变量替换：`{{modid}}`、`{{id}}`、`{{displayName}}`、`{{package}}`、`{{ClassName}}`、`{{stackSize}}`、`{{toolTier}}` 等；
- `ClassName` 由 `id` 转 PascalCase（`ruby_sword` → `RubySword`）；
- 路径模板同样替换；渲染结果必须在项目根内、不得写 `build/`、`.gradle/`、`generated/`；
- 不做复杂模板引擎（条件/循环），需要分支时用多个模板或 `when` 表达式（`always` / `loader:forge` / `param:hasBlockEntity`）；
- 参数由 `template.json` 声明并校验（必填、类型、id 合法、范围），不信任调用方。

### 5.3 合并与冲突

| 目标状态 | 默认行为 |
| --- | --- |
| 文件不存在 | 创建 |
| 已存在且 `merge: "json"` | 深合并（对象合并、数组去重） |
| 已存在且无 merge | 跳过并报告冲突（不覆盖） |
| Java 文件已存在 | 跳过；`merge: "markers"` 留给 v0.4 代码生成 |

- 预览列出：新增 / 修改 / 跳过（原因）/ 越界；
- `template.apply` 必须带 `requestId`，重复请求幂等。

### 5.4 事务与备份

```text
1. 校验参数与模板版本（loader/mcVersion/mappings）
2. 渲染文件清单（不落盘）
3. 预览：新增/修改/跳过
4. 备份目标文件（复用 backupContentFiles，manifest 格式一致）
5. 写入
6. 刷新 structure
7. 失败：用备份恢复并抛错
```

- 写入后不记内容历史（模板是代码/资源骨架，不是内容编辑）；任务 `result` 记录文件与检查结果；
- 模板写入失败不影响已有文件。

### 5.5 测试

- 每个模板固定参数 golden（Java/JSON 逐字节比对）；
- 参数缺失、非法 id、loader 不匹配、mappings 不匹配；
- 冲突不覆盖、json merge 正确、路径越界拒绝；
- 写入失败回滚；
- 渲染幂等（同参数两次结果一致）。

## 6. Phase C：上下文包

### 6.1 组成

`context.pack { taskId, budget? }` 返回：

```json
{
  "task": { "id": "...", "title": "...", "goal": "...", "acceptance": [] },
  "system": { "id": "...", "responsibility": "...", "invariants": [] },
  "templates": [{ "id": "simple-item", "version": 1, "parameters": {} }],
  "api": [{ "class": "net.minecraft.world.item.Item", "signatures": [] }],
  "classes": [{ "id": "class:AbstractLock", "path": "...", "summary": "...", "excerpt": "..." }],
  "resources": [{ "path": "...", "kind": "lang|model|texture|tag" }],
  "invariants": ["..."],
  "allowedPaths": [{ "path": "...", "mode": "modify" }],
  "guardPaths": ["..."],
  "codeRefs": [{ "id": "class:...", "path": "..." }],
  "budget": { "files": 8, "bytes": 12000, "apiClasses": 20, "truncated": [] },
  "apiUnknown": false,
  "stale": false
}
```

- `api` 段来自 `apiRefs`（task + template 合并，去重，最多 20 类 / 4KB）；
- `classes` 段来自 `codeRefs`，解析 `structure.json` 的类与行号，取方法签名 + 可选摘录；
- `resources` 来自模板 `files` 与 task `contextRefs`；
- 任务缺 `templateRefs` 也能打包（只有代码/资源上下文）。

### 6.2 预算与裁剪

- 默认：文件 ≤ 10、字节 ≤ 12KB、API 类 ≤ 20（任一维度超限即裁剪）；
- 裁剪顺序：resources → classes excerpt（只留签名）→ api 方法签名（去参数名/注释）→ 丢弃 `guardPaths` 之外的资源；
- `budget.truncated` 列出被裁剪的项和原因；
- 超预算时仍返回结果，但标记 `truncated`，提示 AI 用 `api.get` / `structure_get` 按需读取。

### 6.3 输出

- JSON（工具返回）；
- Markdown 预览（界面用）：任务、系统、模板、允许路径、API 摘要、代码引用、检查计划；
- 不输出完整 `structure.json`、不输出历史日志、不输出整个仓库。

### 6.4 测试

- 预算裁剪：构造 15 个文件/30KB，验证只保留 10 个/12KB 并标 `truncated`；
- `apiUnknown`：无索引时不出现 api 段，标记 true；
- `codeRefs` 不存在 → 任务 `blocked`（或上下文标记 `missingRefs`）；
- 与 `structure.json` 行号一致。

## 7. Phase D：检查器

### 7.1 检查清单（v0.3.0）

| 检查 id | runner | 行为 |
| --- | --- | --- |
| `allowed-paths` | host | 任务写入/变更只落在 `allowedPaths`，模式匹配 `create`/`modify` |
| `guard-paths` | host | `guardPaths` 无改动 |
| `structure-diff` | host | 相对基线快照，只出现预期变化；派生文件变化算警告 |
| `resource-exists` | host | 模板/任务声明的资源文件存在（模型、贴图、语言、标签） |
| `registration-pair` | host | 物品/方块注册名与资源配对（item → model/texture/lang；block → blockstate/model/blockitem/lang） |
| `lang-key` | host | 物品/方块语言键存在（复用语言索引） |
| `compile-java` | host（可选） | `gradlew compileJava --offline`，超时 120s，输出摘要 |
| `custom` | manual/agent | 任务自定义证据（文本 + 可选文件） |

### 7.2 `structure-diff`

- 任务 `start` 时把当前 `structure.json` 存 `cache/structure/<hash>.json`，写入任务 `baseStructureHash`；
- `verify` 时重新刷新 structure，与快照比较：
  - 阻断：`guardPaths` 变化、未声明的新增/删除文件、注册项/资源变化超出任务范围；
  - 警告：类顺序、行号偏移、`summary.json` / `structure.json` 等派生文件变化；
- 快照缺失时降级为 `allowed-paths` + 标记「未验证结构」。

### 7.3 `compile-java`

- 仅在任务 `verify` 显式声明时执行；
- 需要项目有 `gradlew`、JDK 17；
- `--offline`、超时 120s、stdout 截断到 40 行、结果写入 `result.checks`；
- 失败不自动回滚（由用户决定），但任务不能标 `done`。

### 7.4 测试

- 每个检查的正例/反例；
- `allowed-paths` 通配符与 `create`/`modify`；
- `structure-diff` 的阻断/警告分类；
- `registration-pair` 对物品/方块/标签的配对；
- `compile-java` 用 fixture 工程模拟（不依赖真实 Gradle 时可跳过并返回 `skip`）。

### 8.2 状态机与动作

```text
todo → doing → review → done
        │        │
        └→ blocked ←┘
```

| 动作 | 行为 |
| --- | --- |
| `task.start` | 校验系统/模板/`codeRefs`；快照 structure；状态 `doing`；返回上下文包摘要 |
| `task.apply` | 接收变更集（`{path, content, mode}`）；校验 allowed/guard；预览；备份；写入；刷新 structure；记录 `result` |
| `task.verify` | 跑声明的检查；写 `result.checks`；全部通过且证据齐 → `review`/`done` |
| `task.rollback` | 用 `result.rollbackDir` 恢复本任务文件；状态回 `doing`/`blocked` |

- 所有写动作带 `requestId`，重复请求返回同一结果；
- 已有文件必须带 `expectedRevision` 或内容哈希（`baseRevisions`）；
- 越界路径直接拒绝；
- `done` 需要检查通过 + 证据，不能手工跳过（界面可覆盖，但记录 `manualOverride`）。

### 8.3 应用与回滚

- 变更集来源：模板渲染结果（`template.render`）+ AI 生成的文件内容；
- 预览分类：新增 / 修改 / 跳过 / 越界；
- 备份目录：`$DSH_HOME/mcmods-studio/backups/<项目>/<stamp>-<uuid>-task/`，manifest 复用 `backupContentFiles`；
- 回滚只恢复本任务声明的文件，不碰其他改动；
- 失败时保留备份与报告，状态 `blocked`。

### 8.4 UI

计划页（`PlanTab`）扩展：

1. **任务板**：待做 / 进行中 / 待验证 / 完成 / 阻塞五列；
2. **任务卡片**：系统、目标、模板、验收进度、越界/检查警告；
3. **任务详情**：上下文包预览（Markdown）、允许路径、检查结果、应用/回滚按钮；
4. **模板选择器**：从 `template.list` 选模板，填参数，预览渲染结果；
5. **API 索引状态卡片**：可用/过期/失败原因、统计、刷新按钮（项目页或计划页）；
6. **检查结果**：按检查 id 分组，pass/fail/skip 与摘要。

首版可只做任务板 + 详情 + 模板预览；API 索引状态放在项目详情。

## 10. 验收标准

对齐 [PLAN.md](../PLAN.md) M2：

1. AI 能根据一句想法选择模板并生成任务；
2. 一个任务上下文不超过 10 个文件；
3. AI 查询 `Item.Properties`、`BlockEntity`、`MenuProvider` 能拿到真实签名（含 protected、继承、嵌套类）；
4. 越界修改会被 `allowed-paths` / `structure-diff` 拦下；
5. 模板渲染可预览、可回滚，冲突不覆盖；
6. 任务可 start → apply → verify → rollback，状态与证据可追溯。

## 12. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| Gradle classpath 获取不稳定 | 默认 auto 先精确后静态；失败返回明确 `reason`；不阻塞内容编辑 |
| javap 输出随 JDK 版本变化 | fixture 测试 + 宽松解析；无 JDK 回退类名清单 |
| 索引体积大（数千类） | 按包分片、按需加载、缓存目录可删 |
| 模板写入代码有风险 | 默认不覆盖、写入前备份、写入后检查、可回滚 |
| 预算裁剪导致上下文不足 | `truncated` 标记 + 工具按需读取；任务可重新 pack |
| 任务并发写入 | `requestId` + `baseRevisions` + 备份；冲突拒绝 |
| `compile-java` 依赖本机环境 | 显式声明才执行；失败标 `skip` 而非误判 |
