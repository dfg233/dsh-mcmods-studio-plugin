## 2. 确认凭据契约（D1 落地）

```text
task.confirm → confirmation = {
  id, taskId, revision,
  payloadHash,          // 任务定义 + 变更集预览的 hash
  fileBaselines: [{ path, hash, size }],  // 目标文件当前基线
  confirmedAt, source   // 'user' | 'agent'
}
```

`task.apply` 校验：

1. `confirmation` 存在且未消费；
2. `task.revision` 与凭据一致；
3. 当前 payload 的 hash 与 `payloadHash` 一致；
4. 目标文件基线未变化；
5. 校验通过后在锁内消费（一次性），写入时再复核基线。

失败返回 `CONFIRMATION_REQUIRED` / `CONFIRMATION_STALE` / `CONFLICT`。

## 3. 事务与回滚契约（D2 落地）

```text
apply → transaction:
  backup   → 批次目录 bat-<n>
  write    → 资源写入
  record   → saveTask（同一提交协议内）
  refresh  → 派生数据（失败仅告警）
失败 → 回滚到批次 before-image；恢复失败 → recoveryRequired + backupDir
```

- `result.batches[] = { id, backupDir, files, appliedAt }`；
- `task.rollback { taskId, batchId? }`：默认回滚最近一批；`all: true` 回滚全部批次；
- 旧记录（无 `batches`）按「单批」兼容读取。

## 4. 错误码与响应

| 错误码 | 含义 |
| --- | --- |
| `CONFIRMATION_REQUIRED` | 未确认或确认已消费 |
| `CONFIRMATION_STALE` | 确认后内容/文件基线变化 |
| `CONFLICT` | revision 不匹配（并发写） |
| `DATA_CORRUPT` | 事实 JSON 损坏（fail-closed） |
| `PATH_OUTSIDE` | 路径越出项目真实根或含父级跳转 |
| `EXTRACT_LIMIT` | 解压输出/累计大小超限 |

## 6. 已确认决策（2026-11-17）

- **D1 = A**：写前批准 + 写后验收（两个状态）；
- **D2 = A**：批次栈（每次 apply 一批，可逐批/全部回滚）；
- **D3 = A**：仅单进程（同进程 Promise 队列，文档写明不保证多 Host 同写）；
- **D4 = A**：v0.6.0 = P1–P3 + P5；v0.6.1 = P4 + P6；
- **D5–D9 按建议**：仅本机回环、symlink 默认禁跨真实根、Node ≥ 20、静态索引宁缺勿错、仓库内最小门禁。
