# v0.6.2 计划：注册元数据补全（PATCH）

> 日期：2026-11-18
> 版本：v0.6.2（PATCH）
> 状态：**方案待确认，未实现**
> 来源：v0.6.0 实机反馈——物品属性（耐久/分类/伤害/挖掘等级）未显示；`mod_boat` 等注册类仍被识别成物品。
> 关联：[V0.6.0-PLAN.md](V0.6.0-PLAN.md) P5（注册优先导入）、[V0.6.1-PLAN.md](V0.6.1-PLAN.md)。

## 0. 摘要

1. **注册识别补全**：嵌套泛型 `DeferredRegister<EntityType<X>>` 与实体/其他注册类型不再被误判为物品；
2. **属性提取**：从注册表达式提取耐久、攻击伤害/速度、工具等级/采集等级、护甲值、创造栏分类、食物；
3. **导入写回**：导入时写入上述字段（只填空值，不覆盖用户手改）；
4. **旧条目清理**：reimport / `import.pruneEntries` 清理「其他注册类型」的历史残留（如 `mod_boat`）。

## 1. 根因（已定位）

### 1.1 mod_boat 误判

- `lib/registry-scan.js` 类型正则只匹配简单泛型：
  `/DeferredRegister\s*<\s*([A-Za-z0-9_.]+)\s*>\s+([A-Za-z0-9_]+)/`
  嵌套泛型 `DeferredRegister<EntityType<ModBoatEntity>>` 匹配失败 → `ENTITY_TYPES` 不在类型表 → `mod_boat` 没有被归入「实体注册」；
- 旧扫描 `scanRegistryNames` 把非创造标签文件的 `register("id")` 全当物品，作为回退路径时会把实体带入物品；
- v0.6.0 的 `removed` 只清理「资源可解释」的残留（如 `corn_crop_stageN`），`mod_boat` 无资源 → 旧条目留存。

### 1.2 属性未显示

- `lib/import.js` 的 `syncEntries` 创建条目时统一 `defaultProperties()`，未解析注册表达式；
- TutorialMod 的写法可静态解析：
  - `new Item.Properties().durability(127)` → `maxDamage`；
  - `new SwordItem(Tier, dmg, speed, ...)` → `attackDamage`/`attackSpeed`/`toolTier`；
  - `new PickaxeItem(Tier, ...)` / `ShovelItem` / `AxeItem` / `HoeItem` → `toolTier` + `miningLevel`；
  - `new ArmorItem(Material, ArmorItem.Type.HELMET, ...)` → `armor`；
  - `ModCreativeModeTabs` 的 `output.accept(...)` → `creativeTab`；
  - `new Item(new Item.Properties().food(ModFoods.X))` → `foodNutrition`/`foodSaturation`（需解析 ModFoods 常量）。

## 2. 设计

### 2.1 注册扫描扩展（registry-scan.js）

- 泛型正则改为支持嵌套：`/DeferredRegister\s*<\s*([A-Za-z0-9_.?<>,\s]+?)\s*>\s+([A-Za-z0-9_]+)/`；
- 类型归类增加：`entities`（EntityType）、`blockEntities`、`effects`、`enchantments`、`sounds`、`particles`、`fluids`、`tabs`；
- 返回 `{ blocks, items, creativeTabs, entities, others: { type: [ids] }, warnings }`；
- 导入时把这些集合用于「排除」与「清理候选」。

### 2.2 属性提取（新增 lib/item-props.js）

对每个 `ITEMS.register("id", () -> new Xxx(...))` 捕获构造表达式（支持跨行）：

| 模式 | 字段 |
| --- | --- |
| `.durability(n)` | `maxDamage` |
| `SwordItem(T, dmg, speed, ...)` | `attackDamage`、`attackSpeed`、`toolTier` |
| `PickaxeItem(T, ...)` / `ShovelItem` / `AxeItem` / `HoeItem` | `toolTier`、`miningLevel` |
| `ArmorItem(M, Type.HELMET)` 等 | `armor`（1/3/2/1） |
| `Tiers.X` / 自定义 Tier 常量 | `toolTier`（名称）、`miningLevel`（原版等级映射） |
| `Item.Properties().food(...)` | `foodNutrition`/`foodSaturation`（已知 ModFoods 常量解析；解析不了时留空） |
| `ModCreativeModeTabs` accept 顺序 | `creativeTab` |

规则：

- 只填空值（`null`/`0`/空串），不覆盖已有手改值；
- 解析失败写 `loaderNotes` 提示「属性需人工确认」，不抛错；
- 不猜测复杂表达式（如三元、方法调用结果）。

### 2.3 导入写回（import.js）

- `syncEntries` 创建条目时调用 `extractItemProps(projectPath, modid)`；
- 对新条目填入提取值；对已有条目（merge）只填空字段；
- `reimport` 的 `removed` 增加「实体/其他注册类型的旧条目」（即使无资源）；
- `import.pruneEntries` 同步增加这些类型。

## 5. 风险

| 风险 | 应对 |
| --- | --- |
| 正则提取误判复杂表达式 | 只处理明确模式；失败写提示不猜测 |
| 覆盖用户手改属性 | 只填 `null/0/空`，不覆盖非空值 |
| 自定义 Tier/材质解析不到 | 保留 `toolTier` 名称，数值留空并提示 |
| 实体清理误删手写条目 | 只清理「注册类型集合」内的 id（有注册依据） |
