## 0. 摘要

M2 已经让 AI 知道「依赖里有什么 API」「标准做法长什么样」「这次任务能改哪些文件」。M3 补上最后一公里：**从零生成可编译的工程，并生成、修改真实代码**，且不覆盖手写逻辑。

四块能力：

```text
Gradle 脚手架（一句话 → loader/版本/映射 → 完整可编译工程）
  → 标记区块（只改标记之间的内容）
    → 代码生成器（模板渲染 + diff 预览 + 备份/回滚）
      → 第二批模板（方块实体/菜单、钥匙、网络包、锁类型）
        → Lock 端到端试点（新增电子锁，机械锁行为不变）
```

目标版本 v0.4.0（MINOR，路线里程碑），不改变已有数据格式与接口语义。

## 2. 目标与非目标

**目标**

- 新建项目时可选择或由 AI 推断 loader / MC 版本 / 映射，生成完整可编译的 Gradle 工程；
- 生成物用注释标记包裹，只替换标记之间的内容；标记外原样保留；
- 生成前给出逐文件 diff（新增/修改/追加/跳过/越界），生成后自动备份，失败回滚；
- 第二批 8 个模板覆盖方块实体/菜单、网络包、钥匙、锁类型、配置、创造标签；
- 任务可声明「生成」并复用 M2 的 allowedPaths、structure-diff、compile-java 做验收；
- Lock 试点：新增电子锁类型，机械锁行为不变，编译与行为检查通过。

**非目标**

- 不做完整 IDE：不实现语法高亮、补全、跳转、调试；
- 不做任意 Java 代码生成：模板只出骨架，业务逻辑由 AI 按任务填充；
- 不自动修改未标记的文件（缺失标记时只追加新区块，不改既有行）；
- 不做多 MC 版本；v0.4 脚手架与模板只覆盖 1.20.1 的 forge / neoforge / fabric；
- 不保证离线环境能拉取 Gradle 依赖（脚手架只负责生成工程，构建验证可选）；
- 不做 git 操作与远程同步。

## 3. 总体设计

### 3.1 模块划分

| 新模块 | 职责 |
| --- | --- |
| `lib/scaffold.js` | Gradle 脚手架：参数推断、版本矩阵、模板渲染、预览/应用/回滚 |
| `lib/version-matrix.js` | 版本能力表（loader × MC 版本 × 映射 × Java/Gradle 版本） |
| `lib/markers.js` | 标记区块解析、定位、替换、追加、重复/嵌套检测 |
| `lib/codegen.js` | 生成编排：模板渲染 → 标记替换 → diff → 应用/回滚 |
| `lib/files.js`（可选） | 文件树、文本读写、扩展名白名单、mtime 冲突检测 |
| `templates/scaffold/<loader>/<mcVersion>/` | 脚手架模板（gradle 工程、主类、描述文件、wrapper） |
| `templates/markers/` | 第二批模板（含标记片段） |

数据流：

```text
任务（templateRefs + params）
  → codegen.preview：渲染片段 → 定位标记 → 生成 diff
  → 用户/AI 确认
  → codegen.apply：备份 → 替换/追加/新建 → 刷新 structure
  → task.verify：structure-diff / compile-java
```

### 3.2 标记区块

沿用 [CODEGEN-PLAN](../plans/CODEGEN-PLAN.md) 的语法：

```java
// <mcstudio:generated items>
public static final RegistryObject<Item> RUBY = ITEMS.register("ruby", () -> new Item(new Item.Properties()));
// </mcstudio:generated>
```

规则：

- 一个文件可有多组标记，按 `id` 区分（`items` / `blocks` / `creative_tabs` / `packets` / `config`）；
- 只替换标记之间的内容；标记外原样保留；
- 标记缺失：在目标文件末尾追加一组新标记（`append`）；
- 标记重复或嵌套：直接报错，要求人工修复，不自动合并；
- 标记内容由生成器负责，用户可读但不应手改（README 与注释说明）。

### 3.3 代码生成器

`lib/codegen.js`：

| 函数 | 行为 |
| --- | --- |
| `previewCodegen(projectPath, input)` | 渲染模板 → 逐文件定位标记 → 计算 diff（create/update/append/skip） |
| `applyCodegen(projectPath, input)` | 备份 → 按 diff 写入 → 刷新 structure；失败回滚 |

输入：

```json
{
  "templateRefs": [{ "id": "simple-item", "version": 1, "parameters": {} }],
  "items": ["ruby", "ruby_sword"],
  "markers": { "items": "ModItems.java" }
}
```

- `templateRefs` 复用 M2 模板；模板 manifest 增加 `markers` 声明（见 3.5）；
- `items` 为生成条目的数据来源（物品/方块/钥匙）；
- `markers` 指定标记所在文件（相对项目路径），未指定时用模板默认值。

diff 结构：

```json
{
  "files": [
    { "path": "src/main/java/.../ModItems.java", "action": "update", "marker": "items", "additions": 2, "removals": 0, "diff": "..." },
    { "path": "src/main/resources/assets/.../models/item/ruby.json", "action": "create" }
  ],
  "conflicts": [],
  "outOfBounds": []
}
```

### 3.4 与任务/检查集成

- `codegen.apply` 的写入必须落在任务 `allowedPaths` 内；guard 路径一律拒绝（复用 `matchesPath`）；
- 应用后刷新 `structure.json`，`task.verify` 的 `structure-diff` 可判断「只改了预期注册行」；
- `compile-java` 可选执行，失败不自动回滚但任务不能标 `done`；
- 生成记录写入任务 `result.files`，回滚复用任务备份。

### 3.5 模板扩展

`template.json` 增加：

```json
{
  "files": [
    {
      "path": "src/main/java/{{packagePath}}/registry/ModItems.java",
      "template": "files/mod-items.java.tpl",
      "marker": "items",
      "mode": "marker"
    }
  ]
}
```

- `mode`: `file`（整文件，默认）/ `marker`（只替换标记区块）；
- `marker` 与 `files[].path` 一起定位目标文件；标记缺失时追加。

### 3.6 第二批模板

| 模板 | 输出 | 依赖 API |

## 7. Gradle 脚手架

### 7.1 目标

新建项目时（或对空目录）由 AI 根据一句描述推断参数，生成一个**完整可编译**的 MC 工程，而不是只有 `.mcstudio/` 设计数据。

现状：`createProject` 只建 `.mcstudio/` 与 `docs/`（`lib/meta.js` 注释明确「不生成任何 gradle 或 Java 代码」），用户仍需手抄 MDK。

### 7.2 参数与推断

| 参数 | 来源 |
| --- | --- |
| loader | 用户选择 / AI 从描述推断（forge / neoforge / fabric） |
| minecraft | 版本矩阵（v0.4 仅 1.20.1） |
| mappings | parchment / official / yarn（按 loader 推荐） |
| modid / name / version | 用户输入，AI 按命名规则补全 |
| package / group | `com.example.<modid>` 或用户指定 |
| loaderVersion | 版本矩阵（如 forge 47.4.16、neoforge 47.1.x、fabric loader 0.15.x） |
| javaVersion | 17 |

推断失败或版本不在矩阵内时回退到表单让用户选择，不猜。

### 7.3 生成物

```text
<项目>/
  settings.gradle
  build.gradle
  gradle.properties
  gradle/wrapper/gradle-wrapper.properties
  gradlew / gradlew.bat
  src/main/java/<package>/<ClassName>.java        # 主类 + @Mod 注解
  src/main/resources/META-INF/mods.toml            # forge / neoforge
  src/main/resources/fabric.mod.json               # fabric
  src/main/resources/pack.mcmeta
  .gitignore
```

- 模板放 `templates/scaffold/<loader>/1.20.1/`，变量与 M2 模板一致（`{{packagePath}}` 等）；
- `gradlew` / `gradlew.bat` 与 wrapper jar 从模板复制（不依赖本机 Gradle）；
- 生成后刷新 `structure.json`，可选跑 `gradlew compileJava`（超时 180s，`--offline` 可选）。

### 7.4 流程

```text
scaffold.preview { path, description?, loader?, minecraft?, mappings?, modid?, ... }
  → 推断参数 → 渲染文件清单 → 冲突/越界检查（目录非空默认只写缺失文件）
  → 返回 {params, files[], conflicts[]}
scaffold.apply { path, params, requestId }
  → 备份 → 写入 → 刷新 structure
  → 可选 compileJava → 结果写 result（buildVerified）
  → 失败回滚（保留已生成文件与日志，标记 buildVerified:false）
```

### 7.5 与创建流程集成

- `project.create { ..., scaffold: true, description? }`：创建 `.mcstudio` 后立即走脚手架；
- UI：新建项目弹窗增加「同时生成 Gradle 工程」开关与 loader/版本选择；
- 生成成功后自动登记注册表并进入项目页；失败时保留目录并提示「工程已生成但构建未验证」。

### 7.6 验收

1. 一句话「用 NeoForge 1.20.1 建一个叫 Ruby 的模组」→ 生成完整工程；
2. 文件清单与版本矩阵一致，`gradlew compileJava` 在依赖可获取时通过；
3. 目录非空时 preview 报告冲突，不覆盖已有文件；
4. 构建失败时 `buildVerified:false` 可见，不误报成功；
5. 生成后可继续建物品、套模板、建任务（M2 流程不受影响）。

## 8. Lock 端到端试点

目标：在 `D:\MCmod\Lock - 副本` 上新增「电子锁」类型，机械锁行为不变。

步骤：

1. API 索引刷新（M2）；
2. 建系统卡 `lock-core`（职责、不变量）；
3. 建任务：新增电子锁，`allowedPaths` 含 `ElectronicLock.java`、`AbstractLock.java`、`ModItems.java`、语言/模型资源；`guardPaths` 含网络与机械锁实现；
4. 模板生成：`lock-type` + `uuid-key-item` + `block-entity-menu` + `s2c-sync-packet`；
5. AI 按任务填充业务逻辑（UUID 绑定、序列化、交互）；
6. `task.verify`：allowed-paths / structure-diff / compile-java；
7. 人工游戏内验证：电子钥匙与电子锁 UUID 匹配、重启保持、未上锁门可用、机械锁行为不变。

验收：

- `compileJava` 通过；
- 机械锁原有行为不变（对照测试）；
- 电子锁能开/关、钥匙可绑定；
- 任务 `done` 有检查证据。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| Gradle 依赖下载失败（网络/代理） | 脚手架只生成工程；`compileJava` 可选，失败标 `buildVerified:false`，不误报 |
| loader 版本矩阵不准（Forge/NeoForge/Fabric 差异） | 版本矩阵集中维护；不在矩阵内回退表单，不猜版本 |
| 目录非空时覆盖用户文件 | preview 报告冲突；默认只写缺失文件，不覆盖 |
| 脚手架模板与真实 MDK 漂移 | 模板随插件发版；验收用 `compileJava` 与真实工程对照 |
| 覆盖手写代码 | 只改标记区间；标记缺失只追加；重复/嵌套报错 |
| 注册冲突 | 生成前检查现有注册名；冲突报告不写盘 |
| 模板与项目结构不符 | 模板声明 `packagePath` 与目标路径；`structure-diff` 兜底 |
| 编译环境缺失 | `compile-java` 缺失时 skip，任务不能标 done |
| Lock 试点范围过大 | 先锁类型 + 钥匙 + 菜单，网络包单独一轮 |
| 生成 diff 难读 | UI 显示行数与文件清单，详细 diff 走日志 |
