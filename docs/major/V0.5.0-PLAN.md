## 0. 摘要

M4 三条线：

1. **内容广度**：战利品表、创造标签成员、更多配方类型（切石 / 锻造 / 烟熏 / 营火）；
2. **加载器覆盖**：为关键模板补 NeoForge 变体，评估 Fabric；
3. **可测性能**：100 物品 / 20 模块的基准脚本与目标值，避免「功能可做、工程变慢」。

同时补文档与示例说明，保证 v1.0 前的稳定契约。

## 2. 范围与非目标

### 范围

- 战利品表：方块常规掉落（自身、数量范围、几率、多条目、爆炸条件）；
- 创造标签成员：读取/写入标签成员（1.20.1 代码注册 + 标记区块）；
- 配方：`stonecutting`、`smithing_transform`、`smoking`、`campfire_cooking`；
- 多加载器模板：NeoForge 优先（simple-item、tool-set、block-basic、配方、标签、lang-pair、creative-tab），Fabric 只评估 simple-item + lang；
- 性能基准：脚本 + 目标值 + 记录；
- 文档与示例说明。

### 非目标（留给 v1.0）

- 1.21.1 适配、`.jar` 导入、数据迁移；
- 完整 GUI 重做（继续只读 + 必要按钮）；
- 战利品表的全部特性（entity / fishing / gift / 自定义条件）；
- Fabric 全套模板（只评估 1–2 个）。

## 3. 内容扩展

### 3.1 战利品表

数据路径：`data/<modid>/loot_tables/blocks/<id>.json`。

数据形态（方案）：

```json
{
  "type": "minecraft:block",
  "pools": [{
    "rolls": 1,
    "entries": [{ "type": "minecraft:item", "name": "<modid>:<id>", "functions": [{ "function": "minecraft:set_count", "count": { "min": 1, "max": 3 } }] }],
    "conditions": [{ "condition": "minecraft:survives_explosion" }]
  }]
}
```

- API：`content.loot.get` / `content.loot.preview` / `content.loot.save`；
- UI：物品编辑器新增「掉落」页签（仅方块类；物品无掉落）；
- 模板：`loot-table`（生成上述 JSON，参数 id / count 范围 / 几率）；
- 校验：JSON 结构、`name` 与 modid 一致、方块存在；
- 测试：读写往返、预览 diff、非法字段拒绝。

### 3.2 创造标签成员

1.20.1 Forge 的创造标签是**代码注册**（`DeferredRegister<CreativeModeTab>` + `displayItems`），不是数据文件。方案：

- 模板 `creative-tab` 已有注册骨架（v0.4.5 前）；
- 新增「成员」标记片段：`output.accept(ModItems.<CONST>.get());` 写入 `creative_tab` 标记块；
- API：`content.tab.members({ id })` → 当前成员（解析注册代码/标记）；`content.tab.add` / `remove`；
- UI：物品编辑器「创造标签」选择 + 预览将写入的标记；
- 校验：引用的物品存在；标签注册存在；
- 测试：marker 写入、成员读取、去重。

### 3.3 更多配方类型

在 `RECIPE_TYPES` 增加：

| 类型 | JSON 根 | 关键字段 |
| --- | --- | --- |
| `stonecutting` | `minecraft:stonecutting` | ingredient / result / count |
| `smithing` | `minecraft:smithing_transform` | template / base / addition / result |
| `smoking` | `minecraft:smoking` | ingredient / result / experience / cookingtime |
| `campfire` | `minecraft:campfire_cooking` | ingredient / result / experience / cookingtime |

- API：`content.recipe.get/save/preview` 支持新类型；
- UI：配方页签按类型显示字段；
- 模板：`stonecutting-recipe`、`smithing-recipe`、`smoking-recipe`、`campfire-recipe`；
- 测试：各类型往返、字段校验、模板渲染。

## 4. 多加载器模板

现状：模板 manifest 的 `loaders` 基本是 `['forge']`；MDK 已支持三加载器，但模板没有 NeoForge/Fabric 变体。

策略：

1. 利用 `templates.js` 已有的 `when` 条件，为同一模板增加 `when: { loader: 'neoforge' }` 的文件变体（import 从 `net.minecraftforge.*` → `net.neoforged.*`）；
2. 本轮优先：`simple-item`、`tool-set`、`block-basic`、`shaped-recipe`、`item-tag`、`lang-pair`、`creative-tab`（NeoForge 变体）；
3. Fabric：只评估 `simple-item` + `lang-pair`（yarn/loom 差异大，视工作量决定）；
4. 验收：用真实 MDK（NeoForge 1.20.1）生成模板工程并 `gradlew compileJava`（人工/后台）。

## 5. 性能基线

场景 fixture：100 物品、20 模块、50 任务（脚本生成）。

指标与目标（本机基线，记录环境）：

| 操作 | 目标 |
| --- | --- |
| `workbench.plan` 读取 | < 100ms |
| `context.pack` | < 200ms |
| `summary` 重建 | < 300ms |
| `structure.refresh`（100 物品） | < 2s |
| `plan.export` | < 300ms |

- 脚本：`scripts/benchmark.mjs`（生成 fixture → 计时 → 输出表格 / JSON）；
- 不进入默认测试（避免 CI 波动）；结果记录到 `docs/PERF.md` 或 STATUS 附录；
- 若超过目标，先优化再发版。
