# v0.5.0 计划：完整的简单模组（M4）

> 日期：2026-11-15
> 版本：v0.5.0（MINOR）
> 状态：**方案已确认（2026-11-15），待实施**
> 关联：[PLAN.md](../PLAN.md) M4、[V0.4.5-PLAN.md](../fix/V0.4.5-PLAN.md)、[VERSION-PLAN.md](../VERSION-PLAN.md)、[DATA-FORMAT.md](../DATA-FORMAT.md)
> 定位：v0.5.0 的目标是「**完整的简单模组**」——能通过插件 + agent 做一个覆盖原版内容类型的、可编译可玩的简单模组；复杂功能初步实现。加载器本轮**仅 Forge**。

## 0. 方向与摘要

**「完整的简单模组」定义**：一个新建项目，能够添加/修改**原版拥有的各类内容**（至少覆盖下表的「v0.5 覆盖」列），并用模板 + 代码生成 + 内容编辑完成；「复杂功能」（GUI、网络、维度、结构）达到初步可用。

| 内容类型 | v0.5 目标 |
| --- | --- |
| 物品（普通/工具/食物/盔甲） | 覆盖（现有 + 模板） |
| 方块（普通/方块实体/方块状态） | 覆盖（现有 + 模板） |
| 生物（Entity + 属性 + 刷怪蛋） | 覆盖（新增） |
| 群系（Biome + 特征/放置 + biome modifier） | 覆盖（新增） |
| 声音 / 粒子 | 初步（资源 + 注册骨架） |
| 附魔 / 状态效果 / 药水 | 初步（注册 + 基础字段） |
| 配方 / 战利品表 / 标签 / 语言 / 模型 | 覆盖（配方扩展 + 战利品表新增） |
| 创造标签 | 覆盖（成员写入标记） |
| 结构 / 维度 / 多方块 | 初步（骨架 + 说明，不承诺完整生成） |

三条线：

1. **内容类型覆盖**：补齐生物、群系、声音/粒子、附魔/效果、战利品表、创造标签与更多配方；
2. **复杂功能初步**：GUI/网络/持久化沿用 v0.4 模板，新增实体的生成规则与群系特征；
3. **可测性能与文档**：100 物品 / 20 模块基准、示例模组说明。

## 2. 范围与非目标

### 范围

- 内容：物品（含盔甲）、方块（含方块实体）、生物、群系、声音、粒子、附魔、状态效果、药水、战利品表、创造标签、配方扩展、标签/语言/模型；
- 模板：为上述内容提供 Forge 1.20.1 模板（新增 8–12 个）；
- 生成与校验：注册标记、资源 JSON、编译检查；
- 性能：100 物品 / 20 模块 / 50 任务的基准；
- 示例：一个「完整简单模组」的说明与验收脚本（文档形式）；
- 加载器：**仅 Forge**（NeoForge / Fabric 后续版本）。

### 非目标（留给 v1.0 或后续）

- 1.21.1 适配、`.jar` 导入、数据迁移；
- NeoForge / Fabric 模板；
- 完整 GUI 重做（继续只读 + 必要按钮）；
- 结构/维度/多方块的完整生成（只做骨架与说明）；
- 战利品表的 entity / fishing / gift 等全部特性。

## 3. 内容类型

### 3.1 已有（保持）

物品、方块、配方（shaped/shapeless/furnace）、标签、语言、模型、创造标签骨架、方块实体、菜单/网络/持久化模板。

### 3.2 战利品表

数据：`data/<modid>/loot_tables/blocks/<id>.json`；方块常规掉落（自身、数量范围、几率、多条目、`survives_explosion`）。

- API：`content.loot.get / preview / save`；
- UI：物品编辑器「掉落」页签（仅方块）；
- 模板：`loot-table`；
- 校验：结构、`name` 与 modid 一致、方块存在。

### 3.3 创造标签成员

- 1.20.1 Forge 为代码注册：`output.accept(ModItems.<CONST>.get());` 写入指定标签的标记块；
- API：`content.tab.members / add / remove`；
- UI：物品编辑器「创造标签」选择 + 预览；
- 校验：物品存在、标签注册存在、去重。

### 3.4 配方扩展

新增 `stonecutting`、`smithing_transform`、`smoking`、`campfire_cooking`：

- API：`content.recipe.*` 支持新类型；
- UI：按类型显示字段；
- 模板：`stonecutting-recipe`、`smithing-recipe`、`smoking-recipe`、`campfire-recipe`；
- 测试：各类型往返与校验。

### 3.5 生物（Entity）

- 注册：`DeferredRegister<EntityType<?>>` + `EntityType.Builder`；属性：`EntityAttributeCreationEvent`；刷怪蛋：`ForgeSpawnEggItem`；
- 生成：`SpawnPlacements.register` + `BiomeModifier`（或 `BiomeLoadingEvent` 1.20.1 写法）；
- 实体类骨架：`extends Monster/Animal` + `createAttributes` + `registerGoals`（简单 AI）；
- 模板：`entity-basic`、`spawn-egg`、`entity-attributes`、`entity-spawn`;
- API/UI：内容页新增「生物」条目（名称、类别、尺寸、生命/攻击、刷怪蛋颜色、生成群系）；
- 校验：注册配对（EntityType + 属性 + 刷怪蛋）、资源存在。

### 3.6 群系（Biome）

- 数据：`data/<modid>/worldgen/biome/<id>.json`（1.20.1 数据驱动）+ `worldgen/placed_feature` / `configured_feature`（特征）；
- 注册/注入：`data/<modid>/forge/biome_modifier/*.json`（添加特征/刷怪）；
- 模板：`biome-basic`、`biome-feature`、`biome-modifier`;
- API/UI：内容页「群系」条目（温度、降水、特征列表、生成权重）；
- 校验：JSON 合法、特征引用存在、biome modifier 指向正确。

### 3.7 声音与粒子（初步）

- 声音：`sounds.json` + `SoundEvent` 注册骨架 + 资源占位；
- 粒子：`ParticleType` 注册 + 客户端 Provider 骨架；
- 模板：`sound-basic`、`particle-basic`；
- 校验：JSON 与注册名一致。

### 3.8 附魔 / 状态效果 / 药水（初步）

- 附魔：`Enchantment` 注册骨架（1.20.1 编码式）+ 语言；
- 状态效果：`MobEffect` 注册 + 药水（`Potion`）骨架；
- 模板：`enchantment-basic`、`effect-basic`；
- 校验：注册名与语言键。

## 4. 模板（仅 Forge）

新增模板（估 10–12 个）：

```text
loot-table, stonecutting-recipe, smithing-recipe, smoking-recipe, campfire-recipe,
entity-basic, spawn-egg, entity-attributes, entity-spawn,
biome-basic, biome-feature, biome-modifier,
sound-basic, particle-basic, enchantment-basic, effect-basic
```

- 全部 `loaders: ['forge']`、`mcVersion: 1.20.1`；
- 复用 v0.4 的标记/脚手架机制；
- 每个模板带 `checks`（注册配对、资源存在、JSON 合法）。

## 5. 简单模组示例（端到端）

一个示例项目包含：

- 物品 ×2（红宝石、红宝石剑）；
- 方块 ×1（红宝石块，带掉落）；
- 生物 ×1（红宝石傀儡：属性/刷怪蛋/群系生成）；
- 群系 ×1（红宝石洞窟：特征 + modifier）；
- 声音 ×1、粒子 ×1、附魔 ×1、状态效果 ×1；
- 配方（切石 + 锻造）、战利品表、标签、语言、模型、创造标签成员。

验收：从空项目 → agent 建模块/阶段/任务 → 内容编辑 + 模板生成 → `gradlew compileJava` 通过 → `runClient` 能进游戏并看到内容（人工）。

## 6. 性能基线

场景：100 物品、20 模块、50 任务。

| 操作 | 目标 |
| --- | --- |
| `workbench.plan` | < 100ms |
| `context.pack` | < 200ms |
| `summary` 重建 | < 300ms |
| `structure.refresh`（100 物品） | < 2s |
| `plan.export` | < 300ms |

- 脚本 `scripts/benchmark.mjs`（fixture → 计时 → 表格/JSON）；
- 不进入默认测试；结果记录 `docs/PERF.md`。

## 7. 接口与数据变更

- 动作：`content.loot.*`、`content.tab.*`、`content.entity.*`、`content.biome.*`、`content.sound.*`、`content.particle.*`、`content.enchantment.*`、`content.effect.*` → 动作数 86 → 110 左右（具体以实现为准）；

## 10. 风险

| 风险 | 应对 |
| --- | --- |
| 生物/群系代码差异大 | 只做骨架 + 标记；编译验证兜底 |
| 群系 1.20.1 数据驱动复杂 | 先做 JSON 模板 + 校验，复杂特征后续 |
| 模板数量膨胀 | 只做高频类型；模板可组合 |
| 性能基线受机器影响 | 固定 fixture + 记录环境 |
| 示例工程耗时 | 文档说明 + 脚本生成，不提交二进制 |

## 11. 已确认的决策（2026-11-15）

1. **加载器**：本轮**仅 Forge**，NeoForge / Fabric 暂不考虑。
2. **方向**：做「完整的简单模组」——覆盖原版内容类型（方块、物品、生物、群系等），复杂功能初步实现。
3. **战利品表**：只做方块常规掉落。
4. **创造标签**：成员写入代码标记（1.20.1 只能代码注册）。
5. **性能**：采用第 6 节目标（本机基线）。
6. **示例**：文档说明 + 脚本形式，不提交二进制示例工程。
